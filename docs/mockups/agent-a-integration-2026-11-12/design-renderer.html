4. 댓글에서 새 본문까지: 실행 주체를 한 번만 선택

가장 중요한 추가 계약: 외부 담당 실행 모드
현재 Agent-A는 새 댓글을 저장하면 자체 답변을 요청합니다. IAMCEO 직원에게 맡기려면 문서/요청별 실행 소유자를 서버가 확정하고, 자체 답변·자체 구현 경로를 함께 실행하지 않도록 해야 합니다. 외부 실행자 수신·결과/제안 제출·중단 확인 계약은 문서에 없습니다. 기존 API를 억지로 재사용해 구현됐다고 표시하지 않습니다.
  1. 대표가 자료 A v1에서 요청. 의견/질문/수정 요청을 구분합니다. IAMCEO가 출처 문서·snapshot·댓글·task·담당/배정을 고정하고 수신 기록을 남깁니다. 단순 질문은 답변만, 수정 요청은 변경안까지 준비합니다.
  2. 서버가 한 곳에 전달. 현재 IAMCEO의 총괄 배정·직원 대기열 경로를 사용합니다. 접수는 실행 시작/완료가 아닙니다. 같은 직원의 A/B는 순차 처리하고, 다른 작업의 요약은 필요한 경우만 입력합니다.
  3. 직원이 근거와 결과를 제출. 원래 요청·실행 ID, 읽은 버전, 변경 이유·검증·미결과 정확한 제안을 반환합니다. Agent-A 엔진이 권한과 read-set을 고정합니다. 답변이 도착해도 본문은 그대로입니다.
  4. 대표가 변경 전후를 보고 명시 수락/거절. 선택한 문서 제안만 수락합니다. 헤더 검토 Save나 개발 결과 Save와 구분합니다. 구버전/배정 충돌은 재검토로 보냅니다.
  5. 저장 결과와 실제 표시를 대조. DB 저장 후 현재 정본을 다시 읽고 새 본문이 표시되는지 확인합니다. 응답 유실은 ‘미확인’; 중복 적용 대신 원래 요청 결과를 조회합니다. 원래 댓글은 v1에 남습니다.
  6. 업무 대화에는 한 결과 링크. 결정/이유·새 버전·검증·미결과 원문 참조만 연결합니다. 업무 대화에서 수정 내용을 다시 복사해 별도 스레드를 만들지 않습니다.

현재/장래 구분: IAMCEO task 필터는 실제 CLI 모델 문맥의 완전 분리를 뜻하지 않습니다. f_k134NYyhbo3e의 상사+task별 실행은 별도 설계입니다. 이번 통합은 그 구현을 전제로 하지 않습니다. 현재 총괄의 직접 조사/구현 금지, 직원 간 호출 제약도 임의 해제하지 않습니다.

담당 교체 뒤 늦은 답이전 배정의 결과로 보존. 새 담당이 출처·근거를 인계 검토하고 새 제안으로 채택해야 쓰기 가능. 최초 배정 기록은 수정하지 않음.‘이전 담당 결과 · 인계 검토 필요’. 자동 반영 안 함.

저장 응답 유실·조회 실패정확한 명령/제안의 처리 결과부터 대조. 같은 내용 재시도는 같은 중복키; 다른 내용은 새 키. 확인 전 새 버전 생성이나 완료 요약 금지.‘저장 결과 미확인’ + 결과 재조회. 실패 시 원문·입력 유지.

Agent-A의 중단 API/보존은 §7, 오류는 §10, 원자적 변경·receipt는 §11. IAMCEO 직원 중단과 Agent-A 중단을 연결하는 부분은 신규 어댑터 계약입니다. 개발 담당의 기존 중단 작업은 건드리지 않습니다.

6. 접속·동기화·복구를 위한 최소 조건

인증과 연결 범위

Agent-A는 loopback 서버와 Tailscale Serve의 루프백·정확한 호스트·허용 사용자 헤더를 함께 확인하며, 선택적 토큰/Access 인증도 적용될 수 있습니다(§13). IAMCEO 로그인만으로 Agent-A 권한을 취득한다고 가정하지 않습니다. 서버 어댑터는 Agent-A가 정상 지원하는 인증 경로를 별도로 확인해야 합니다. Tailscale 사용자 헤더 위조, 대표 접속 코드 재사용, 다른 직원 토큰 사용은 설계에 없습니다.

개인 도메인은 302 이동이며 쿼리를 전달하지 않습니다. artifact/review 링크는 승인된 최종 서비스 origin을 고정합니다. 모든 임의 URL을 서버가 대신 가져오는 프록시로 만들지 않습니다. 자격 정보는 서버 설정에만 두고 HTML·URL·댓글·캡처에는 넣지 않습니다.

API 연동은 브라우저가 직접 교차 출처 호출하는 방식보다 서버 간 호출을 권합니다. 그렇더라도 인증 계약 확인이 먼저입니다. 기존 IAMCEO 자료 뷰어의 connect-src 'none'과 중첩 iframe 차단을 풀지 않고, 실제 통합은 제품 UI에서 처리합니다. 현재 공개된 헤더 관찰만으로 CORS/CSP 호환성을 보증할 수 없습니다.

확인된 API와 아직 없는 연결점

문서 §12는 GET /api/artifacts, GET /api/artifacts/:id, POST .../commands, POST /api/plannotator/sessions, /api/external-annotations, /api/plannotator/comment-proposals와 .../approve, /api/ai/history·/query·/abort 등 경로를 열거합니다. 검토 세션 열기는 쓰기 요청이며 이번 조사에서는 호출하지 않았습니다.

정확한 요청 본문/인증 헤더·외부 실행자·웹훅·이벤트 구독·완료 callback은 원문 지도만으로 확정되지 않습니다. POST 문서/댓글로 직원 결과를 주입할 수 있다고 가정하지 않습니다. Agent-A의 task_id나 대화 branch도 IAMCEO의 task/run과 동일하지 않습니다.

조회·outbox·중복 억제 · 신규 운영 제안

문서에 웹훅 보장이 없어 처음에는 조회 어댑터를 제안합니다. 열 때/명시 새로고침/본인 요청 대기 중에만 조회합니다. 대기 중 3초→10초→30초, 탭 숨김 시 중지, 복귀 시 재조회는 시작 가설입니다. 요청/상태 변화가 없으면 중단하고 서버 부하와 알림 지연으로 조정합니다. 일반 AI query의 스트리밍을 전체 문서 이벤트 구독으로 간주하지 않습니다.

IAMCEO는 원래 댓글/전달/배정/실행의 상관 ID를 저장하고, 업무 요약 알림은 원래 이벤트+결과 버전의 중복키로 한 번만 생성합니다. 전달 의도와 outbox를 같은 트랜잭션에 저장하고 수신 ack·실패 횟수를 남기는 부분은 새 개발입니다. Agent-A 내부 receipt와 동일한 기능이 이미 IAMCEO에 있다는 뜻이 아닙니다.

네트워크 오류는 제한 재시도, 인증 거절은 설정 확인 대기, 버전 충돌은 새 검토, 결과 불명은 원래 요청 대조로 분기합니다. 적용 명령은 정본 엔진의 실제 idempotency 계약 확인 뒤에만 재전송합니다. 서버 재시작 뒤에도 로컬 선택 화면/모델 기억 대신 저장된 요청과 결과를 기준으로 복구합니다.

7. Hindsight에는 확정한 판단과 결과만

자료의 채택한 결정/이유·적용 범위·원래 댓글/정본 버전·수락한 제안·검증/실제 결과를 IAMCEO의 선별 기록 접점에 후보로 넘기는 설계입니다. 모든 댓글·답변·초안·거절안을 자동 업로드하지 않습니다. 대표의 선택과 실제 품질 검증은 다른 근거로 남깁니다. 정정은 이전 기록과 대체 관계를 연결합니다.

현재 w3가 구현 중인 선별 기록·업무 전 검색 코드는 변경하지 않습니다. 이번에 검색/업로드/피드백을 호출하지 않았습니다. 정확한 전달 스키마는 기존 접점 계약에 맞춰 후속 확인하며, 실행 상태·권한·문서 정본은 Hindsight 검색 결과가 대신하지 않습니다.

8. 가장 작게 도입하고 검증하는 범위

1단계 · 확인 가능한 연결

기존 자료를 보존한 채 문서 하나를 명시 연결. Agent-A 정본과 원래 검토로 여는 경로, 버전/소유 표시부터 검증합니다. 링크 단계에서는 Agent-A 자체 실행만 사용하며 IAMCEO 직원 자동 전달은 켜지 않습니다.

2단계 · 이 목업의 목표

Markdown A/B, 버전 전체 댓글·답글·변경 전후·수락/거절·업무 요약·오류. IAMCEO 담당 모드는 인증과 외부 실행자/제안 제출 계약을 먼저 보완하고 자체 AI 자동 실행과 배타적으로 운영합니다.

두 단계는 도입 제안입니다. 별도 제품/프로젝트 구조 체험판, 여러 문서 원자 승인, 이미지/PDF 정밀 위치 댓글, 개발 패치 자동 적용·push·배포, Hindsight 연동 변경은 첫 범위에 없습니다.

  1. A v1 요청 → B 이동 → A 알림으로 원래 v1 댓글을 연다. B 내용/스레드는 변하지 않는다.
  2. 답변만인 요청에는 불필요한 수락을 요구하지 않는다. 수정안은 전후를 보고 명시 반영/거절한다.
  3. 반영 시 새 버전 본문 표시를 확인한다. v1 원문/댓글은 유지되고, 업무 대화의 링크는 원래 댓글을 연다.
  4. 담당 교체의 늦은 답은 자동 적용되지 않는다. 최신본 충돌은 새 제안으로 검토하며 기존 이력을 보존한다.
  5. 저장 응답 유실은 미확인으로 남기고 조회 후 한 버전만 확인한다. 중단 ack 전에는 완료로 표시하지 않는다.
  6. 실제 도입 수용 기준: 한 요청당 실행자 1곳, 원문/초안 보존, 재시작 복구, 권한 검사, 정본+Viewer 대조, 중복 알림/적용 없음. 이 항목들은 목업 검증만으로 제품 통과가 되지 않는다.
남은 핵심 판단
목표는 IAMCEO 직원에게 실행을 맡기되 Agent-A는 정본·검토 엔진으로 쓰는 방향을 추천합니다. 이를 선택하면 외부 실행자 계약을 추가해야 합니다. 기존 Agent-A 자체 실행을 먼저 그대로 사용할지, 직원 연결까지 첫 통합 범위로 삼을지는 이번 목업을 보고 정할 수 있습니다. 승인된 것으로 쓰지 않습니다.
