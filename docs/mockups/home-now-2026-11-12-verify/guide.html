홈 현황은 네 줄로,
지난 기록 대신 지금의 상태를 씁니다

고정 순서: 현재 → 진행 → 대표 차례 → 다음.
전체 250자 이내를 상한으로 삼고, 보통 80~140자로 씁니다. 200자를 채우려 늘리지 않습니다. 한 줄은 한 역할만 맡습니다.

현재 프로젝트에 바로 쓸 본문

현재: 대화 카드 사용 가능.
진행: 메인 통합·대화 수정 시험.
대표 차례: 없음.
다음: 시험 후 수정 적용→Agent-A 체험판.

자료 전달 직후 사용할 스냅샷입니다. 현황 작성 업무는 완료로 빠집니다. 등록 직전 도착한 새 보고를 반영했습니다. ‘체험판’은 다음 예정이며, 수정 적용과 메인 통합은 아직 완료 보고가 없습니다.

복사할 고정 틀

현재: [지금 쓸 수 있는 결과/전체 상태].
진행: [실제 움직이는 일 1~2건과 단계].
대표 차례: [열린 판단/할 일 또는 없음].
다음: [확정된 다음 행동과 선후].

실제 줄바꿈 세 개, 빈 줄 없음. 제목·번호·불릿·코드 블록·굵은 글씨를 본문에 넣지 않습니다. 문장 안에서는 가운데점으로 병렬, 화살표로 선후를 표시합니다.

총괄에게 그대로 줄 작성 프롬프트

너는 IAMCEO 홈의 ‘지금 상황’을 작성하는 총괄이다. 대표가 5초 안에 현재·진행·자기 차례·다음을 구분하도록 쓴다. 실제 일을 실행하거나 직원에게 보고를 다시 요청하지 않는다.

입력
- 기준 시각과 현재 project_now 본문
- 진행판: 업무명·칸·담당·갱신 시각·선행 조건
- 열린 결재/대표 할 일: 현재 상태·요청 내용·출처
- 최근 원본 보고와 정정 관계, 대표 지시·결재 답: 시각·범위·실제 단계·근거 참조
입력이 없거나 낡으면 그 범위는 확인되지 않은 것으로 다룬다.

사실을 고르는 규칙
1. 현재 대표 원문과 승인 범위를 먼저 확인한다. 정정된 보고는 최신 정정으로 대체한다. 새 요청·승인은 의도와 권한의 근거이며 완료의 근거가 아니다.
2. 현재에 영향을 주는 중단·지연·오류·대표 판단을 우선 드러낸다. 그다음 실제 움직이는 핵심 업무를 최대 2건 고른다. 나머지 진행은 필요할 때 ‘나머지는 팀 진행판’으로 안내하고 나열하지 않는다.
3. 진행판의 ‘진행 중’이나 배정/수신 확인만으로 착수를 단정하지 않는다. 실제 최근 보고의 단계와 선행 조건으로 요청·예정·착수·검사·적용·완료·막힘·승인 대기를 구분한다.
4. 같은 말처럼 보여도 대상과 환경을 맞춘다. 대표 화면에서 사용 가능과 메인 통합 완료는 다르다. 시험 중을 정상/완료로, 승인됨을 적용됨으로 쓰지 않는다.
5. 대표 차례는 실제 열린 결재/대표 할 일만 적는다. 직원 응답 대기나 내부 검사 대기를 대표 일로 바꾸지 않는다. 열린 항목이 확인되면 행동과 위치를 짧게 쓴다. 확인된 열린 항목이 없으면 ‘없음’, 조회 근거가 없으면 ‘확인 필요’라고 쓴다.
6. 충돌은 출처·시각·정정 관계·대상/범위를 대조한다. 원본으로 해결되지 않으면 ‘진행 여부 확인 대기’처럼 불확실성을 남긴다. 오래된 메모를 현재 실행으로 재사용하거나 임의로 완료 처리하지 않는다.
7. 과거 이력·끝난 기능 목록·반복 주의·직원 세션 내부·커밋/DB/시험 수치는 뺀다. 새 직원 안 만들었다, 푸시 안 했다 같은 반복 문장도 뺀다. 현재 판단에 필요한 예외만 짧게 쓰고 근거는 원래 보고/자료에 둔다.

출력
아래 네 줄의 project_now 본문만 출력한다. 제목·해설·자기평가·출처 목록·마크다운 장식은 붙이지 않는다. 실제 줄바꿈 세 개를 쓰고, 문자 그대로의 역슬래시+n이나 빈 줄을 넣지 않는다.
현재: [지금 쓸 수 있는 결과/전체 상태. 중요한 막힘은 우선 표시]
진행: [실제로 움직이는 핵심 1~2건과 단계. 없으면 없음]
대표 차례: [열린 판단/할 일과 위치. 없으면 없음]
다음: [확정된 다음 행동과 선후. 미정이면 미정]

길이와 갱신
- 공백·문장부호·줄바꿈을 포함해 250자 이내. 보통 80~140자로 더 짧게 쓴다. 폰에서 접히면 중복 수식어와 두 번째 진행 항목부터 덜어낸다. 상태·부정·대표 행동은 자르지 않는다.
- 진행 핵심은 최대 2건. 다음은 이미 정해진 1~2단계만 쓰고, 진행 없는 일을 새로 만들지 않는다.
- 착수/검사/적용/완료/막힘/중단의 변화, 새 대표 결정·정정, 열린 결재/할 일의 생성·종료, 우선순위/선후 변경 때 현재 스냅샷 전체를 다시 쓴다. 상태 변화가 없으면 덧붙이거나 반복 갱신하지 않는다.
- 게시 직전에 최신 보고·열린 항목을 다시 대조한다. 지난 문단 뒤에 새 사실을 누적하지 않는다.

각 줄에서 딱 하나씩 답할 것

  • 현재: 지금 사용할 수 있는 결과와 전체 상태. 장애가 사용을 막으면 사용 가능한 기능보다 장애부터 씁니다. 늘 끝난 기능을 반복하는 목록이 아닙니다.
  • 진행: 실제 최근 실행 보고가 있는 일과 현재 단계. 세 건 이상이면 중단/오류 → 대표 판단으로 막힌 일 → 핵심 선행 업무 → 나머지 순으로 고릅니다. 담당 이름은 구분에 꼭 필요할 때만 씁니다.
  • 대표 차례: 열린 카드의 행동과 위치. 두 건까지 짧게, 더 많으면 ‘결재 3건 확인 · 결재함’처럼 수와 위치를 안내합니다. 답이 끝난 카드나 직원 내부 대기를 넣지 않습니다.
  • 다음: 확정된 후속 행동. 동시에 할 일이면 가운데점, 선행 업무가 끝나야 하면 화살표를 씁니다. 아직 계획만 받았다면 ‘예정’, 아직 정하지 않았다면 ‘미정’입니다.

짧은 예시 네 가지

아래는 가정한 상황입니다. 현재 프로젝트의 실제 진행/결재가 아닙니다.

정상 진행

현재: 소개서 초안 검토 가능.
진행: 수정 문구 작성 중.
대표 차례: 없음.
다음: 수정안 확인→새 버전 저장.

‘검토 가능’과 ‘작성 중’을 분리합니다.

대표 결정 대기

현재: 수정안 준비, 반영은 대기.
진행: 없음. 선택을 기다립니다.
대표 차례: 수정안 채택 여부 · 결재함.
다음: 답변에 따라 반영 또는 재작성.

실제 열린 결재가 있을 때만 이렇게 씁니다.

막힘

현재: 연결 오류로 자료 수신 중단.
진행: 오류 원인 확인 중.
대표 차례: 없음.
다음: 원인 확인→복구 경로 정리.

원인 미확인 상태에서 복구 완료·재시작 예정으로 앞당기지 않습니다.

진행 일 없음

현재: 요청한 안내문 전달 완료.
진행: 없음.
대표 차례: 없음.
다음: 미정. 새 지시 대기.

다음 일이 없으면 새 일을 만들어 채우지 않습니다.

이런 문구는 빼거나 고칩니다

“기능 구현·정상화·검증·적용·메인 통합 완료”
→ 확인한 마지막 단계만 씁니다. 현재 사례는 “대화 카드 사용 가능 / 메인 통합·대화 수정 시험”입니다.

“진행판에 있으니 작업 대화 오류 수정 중”
→ 이전 수신 보고만 있을 때는 다음 줄에 둡니다. 새 원인/수정 시험 보고가 도착한 뒤에만 진행 줄로 올립니다.

“결재 기다리는 중”
→ 실제 열린 카드가 있으면 “대표 차례: 채택 여부 · 결재함.” 이미 답했다면 승인 대기로 남기지 않습니다.

“모든 시험 통과, 문제없음, 직원 세션 유지, 커밋…, 배포 안 함…”
→ 홈에서는 판단에 영향을 주는 현재 상태만. 숫자·내부 근거는 원래 보고로 보냅니다.

“어제 A 완료. 이후 B 진행. 방금 C도…”
→ 덧붙이지 않고 네 줄 전체를 새 스냅샷으로 바꿉니다.

길이·줄바꿈·폰 확인

현재 적용 문구의 글자 수와 폰 표시는 최신 예시로 다시 확인합니다. 로컬 렌더에서 자료 자체는 320/390px 가로 넘침이 없었고, 현행 홈과 같은 글자 크기·행간·5줄 높이를 재현한 미리보기에서도 본문이 잘리지 않았습니다(320px: 화면상 5줄, 390px: 4줄). 실제 대표 앱·다른 글자 크기 설정은 확인하지 않았습니다. 외부 조사·대규모 회귀 시험·AI 호출은 하지 않았습니다.

현재 홈은 ‘논리 네 줄’이어도 폰에서 줄이 감기면 기본 높이를 넘을 수 있습니다. 250자 이내는 표시 보장이 아닙니다. 접힌 내용을 끝까지 읽어야 대표 차례가 드러나는 긴 글은 피합니다. 기본 네 라벨의 순서를 바꾸기보다 각 줄을 줄입니다.

읽기 확인한 출처·범위와 현재 사실의 근거

홈 출처: project_now(text) → setProjectNow → 프로젝트 now → Home.tsx / NowCard. Markdown 렌더러는 breaks: true라 실제 줄바꿈을 지원합니다. 저장 도구는 비어 있지 않은 문자열을 받으며 해당 스키마에 250자 상한은 없습니다. 250자는 이번 운영 권장 상한입니다.

표시 제약: home.css는 14.5px·행간 1.6, 기본 최대 높이 5줄·overflow hidden. 넘치면 ‘더 보기’를 제공합니다. 홈·팀은 큰 현황 카드를 쓰고 다른 화면의 머리줄은 한 줄로 접힐 수 있습니다. 읽은 범위는 Home.tsx·home.css·ui.tsx·Shell.tsx·agent-tools.ts·orchestrator.ts·store.ts이며 제품 변경은 하지 않았습니다.

이 비서에게 board 도구는 노출되지 않아 우회 호출하지 않았습니다. boardView가 읽는 같은 프로젝트의 now·열린 결재·미완료 할 일·진행판을 기존 DB의 읽기 전용 연결로 대조했습니다. 열린 결재 0건·미완료 대표 할 일 0건. 실제 저장된 현황은 실제 줄바꿈 3개이며 문자열 역슬래시+n은 없었습니다.
