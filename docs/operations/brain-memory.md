# IAMCEO 활동 보관과 기억 활용

IAMCEO는 기억 연결이 켜진 프로젝트의 지시·대화·업무·완료 기준·단계·관계·결재·자료·할 일·전달 기록을 hj-brain에 자동 보관한다. 기존에 남아 있는 원본부터 보관하며, 이후 변경은 별도 버전으로 남긴다. 시작 시와 주기적인 점검으로 누락을 메우고, 실시간 변경은 해당 원본만 처리한다.

대표 원문, 직원 보고와 해석, 서버 상태를 구분한다. 원본 ID·업무·화자·시각을 유지하고 긴 원문은 순서와 전체 수가 있는 조각으로 나눈다. 알려진 접속 코드·서비스 키·직원 토큰과 인증값은 가린다. 첨부는 연결과 메타데이터를 보관하며 바이너리 전문을 업로드하지 않는다. 이미 삭제된 원본을 복원하는 기능은 아니다. 다른 앱이나 이 개발 대화의 수집까지 의미하지 않는다.

직원에게 새 지시가 전달되기 전 관련 기억을 찾아 붙이고, 필요하면 `memory_search`와 `memory_get`으로 추가 확인한다. 검색 범위는 해당 프로젝트다. 같은 직원·업무·검색어의 최근 결과는 다시 사용할 수 있다. 기억은 현재 대표 지시나 승인보다 앞서지 않으며, 보관된 보고가 검증된 사실이나 자동 채택 규칙으로 바뀌지 않는다.

직원은 받은 타 업무 기억의 활용 결과를 `memory_feedback`에 남긴 뒤 완료·막힘을 보고한다. 실제 도움은 `helped`, 도움 없음은 `did_not_help`, 반례는 `contradicted`, 적용하지 않은 경우는 `not_used`로 구체적인 이유를 적는다. 성공 여부에서 평가를 추정하지 않는다. `not_used`는 투표하지 않고 이유를 보관한다. 실제 전달 영수증이 있는 새 노출부터 적용하며, 과거 검색 전체에 평가를 소급 요구하지 않는다. 여러 업무를 한 번에 받은 총괄도 업무별로 구분한다.

원문과 명시 평가는 SQLite의 영속 대기열에 먼저 저장한다. 일시 장애·서버 재시작·원격 응답 유실 후에는 같은 사건 ID로 이어 보낸다. 원격 영수증을 확인해야 전송 완료가 된다. 네트워크 실패가 여섯 번이라는 이유로 원문을 버리지 않는다. 잘못된 본문 등 영구 거절은 상태와 사유를 보존한다. 피드백의 네트워크 전송 대기가 직원의 보고를 막지는 않는다.

## 연결 설정

환경 변수 `IAMCEO_MEMORY_URL`과 `IAMCEO_MEMORY_KEY_FILE`이 둘 다 있으면 이를 사용한다. 환경 설정이 없으면 런타임 홈의 `development-memory.json`을 읽는다. 불완전한 환경 설정을 다른 값으로 조용히 대체하지 않는다.

```json
{
  "baseUrl": "http://127.0.0.1:8892",
  "keyFile": "/absolute/private/path/api-key",
  "projects": ["legacy-project-id"]
}
```

이 파일에는 서비스 키의 경로만 넣는다. 파일과 키는 Git 밖에서 권한 0600으로 관리한다. `projects` 목록은 기억 사용 여부를 아직 저장하지 않은 이전 프로젝트에 적용한다. 명시적으로 끈 값은 덮지 않고, 새 프로젝트는 기존 제품 정책대로 기억을 켠 상태로 생성된다. 루프백 또는 Tailscale HTTPS 주소를 사용한다.

`/api/runtime`의 `memory`에는 연결 상태, 업로드의 대기·전송·거절 수와 마지막 오류, 피드백의 미평가·전달 대기·전송 대기·전송 완료·미사용·거절 수가 표시된다. 연결 상태가 정상이어도 전송 대기열이 남을 수 있으므로 함께 확인한다. 기존 실패 기록의 재처리는 원격 사건 ID와 대조한 뒤 수행하며 원문·사건 ID·누적 시도 수를 초기화하지 않는다.

실행 상한·직원 세션·대화·결재는 이 기능의 설정 대상이 아니다. 배포 시 웹서비스만 재시작하고, 같은 원격 main의 빌드인지와 로컬·Tailscale 경로를 확인한다. 개인 판례 분석의 자료 범위·모델·예산·사용 이력도 변경하지 않는다.
