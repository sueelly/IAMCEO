# 총괄의 조정 전용 실행 권한

총괄은 업무 계약·배정·직원 관리·상태와 보고 조회·비동기 최종 확인을 담당한다. 제품 파일 작성, 코드 실행, 시험, 배포와 네이티브 하위 에이전트 실행은 담당 직원에게 맡긴다.

## 서버 도구 경계

`server/agent-tools.ts`의 명시적 허용 목록을 도구 조회와 호출 승인에 함께 적용한다. 총괄은 `file`, `server_backup`, `terminal_input`, `team_close`를 호출할 수 없다. 앞으로 직원 도구가 추가되어도 총괄에게 자동으로 상속되지 않는다. `team_sleep(force: true)`도 거절하므로 실행·승인 대기 조건을 강제로 건너뛸 수 없다.

총괄은 보고에 직원이 등록한 자료 id를 연결하고, `terminal_read`로 승인 창을 확인한다. 실제 선택과 터미널 조작은 대표 화면에 남는다. 직원의 자료 작성과 대표의 기존 터미널 제어 경로는 유지한다.

## 제공자별 실행

| 경로 | 적용하는 제한 |
| --- | --- |
| Claude core·headless·herdr | `--tools Read,Glob,Grep`로 네이티브 읽기만 허용하고 `--strict-mcp-config`로 IAMCEO가 전달한 MCP만 사용한다. 총괄에는 권한 우회 모드를 넘기지 않는다. |
| Codex core | `shell_tool=false`로 명령 실행과 패치를 제거한다. 네이티브 하위 에이전트·앱·플러그인·훅·브라우저·컴퓨터 조작·이미지 생성·코드 모드를 비활성화한다. 읽기 전용 샌드박스와 승인 확장 금지를 적용한다. |
| Antigravity core | 검증된 네이티브 도구 허용 목록이 없어 총괄 실행을 거절한다. 직원 실행은 기존대로 유지한다. |

Codex의 설정 테이블은 병합되므로 빈 `mcp_servers` 값만으로 외부 MCP를 제거할 수 없다. 총괄을 시작하기 전에 같은 작업 폴더·Codex 설정 루트에서 `codex mcp list --json`을 읽고 IAMCEO 이외의 서버를 실행 인자로 비활성화한다. 목록 확인 실패, 잘못된 응답 또는 안전하게 옵션으로 표현할 수 없는 서버 이름은 실행 거절로 처리한다. 목록 원문과 자격 증명은 오류에 남기지 않는다. 사용자 전역 설정 파일은 고치지 않는다.

기존 실행 중인 턴이나 승인 창은 중단하지 않는다. 관리되는 기존 총괄은 쉬는 시점에 같은 대화를 새 권한으로 이어 열고, 갱신 실패 시 입력을 보존한다. 긴급 입력도 옛 권한으로 보내지 않는다. 대표에게서 넘겨받은 기존 세션은 자동으로 닫지 않으며 권한을 확인할 수 없는 동안 새 입력을 보류한다. IAMCEO가 관리하지 않는 외부 CLI 자체의 권한을 바꾸는 기능은 아니다.

관리되는 Codex 총괄은 `board`·`roster`·`task_trace`로 상황을 조회하고, `status`·`post`로 상태와 보고를 기록한다. `team_assign`으로 기존 서버의 프로젝트·업무 계약 검사를 거쳐 담당 직원에게 지시를 전달한다. CLI는 이 여섯 도구에만 총괄용 개별 호출 설정을 적용한다. 설치된 Codex와 로컬 모의 모델을 사용해 보고·배정이 MCP에 도달하고 직원 중단 요청은 승인 정책에서 거절되는지 검사한다.

전담 최종 검수 직원의 Codex 세션은 역할에 허용된 상태·업무 근거 조회, 보고와 검수 판정 도구를 대화형 승인 없이 호출한다. 제작용 셸과 파일 편집 도구는 총괄과 같은 방식으로 제한한다. 설치된 Codex와 로컬 모의 모델을 통해 검수 도구 호출을 확인했다.

## 검증

`tests/conductor-policy.test.ts`는 서버의 직접 호출 거절, 직원 제작 유지, 제공자 실행 인자, 기존 대화 갱신, 승인 대기 보존, 갱신 실패와 긴급 입력을 검사한다. 원래 파일 게시 회귀 검사는 직원으로 수행하며 대표 터미널 API 검사도 유지한다.

설치된 Codex의 실제 모델 요청에 들어가는 도구를 확인하려면 다음을 실행한다.

```sh
IAMCEO_CODEX_POLICY_BIN=/opt/homebrew/bin/codex bun test tests/conductor-codex-native.test.ts
```

이 검사는 임시 설정과 로컬 가짜 모델 서버를 사용한다. 실제 계정 인증이나 모델 호출을 사용하지 않는다. 2026-11-18의 Codex 0.167.0에서 수정 전에는 `exec_command`와 `multi_agent_v1`이 노출되어 실패했고, 수정 후에는 노출되지 않고 외부 MCP가 시작되지 않아 통과했다. 새 CLI 판으로 변경할 때 이 검사를 다시 실행한다. Claude core·headless 실행 구성 회귀 검사는 통과했다. herdr에도 같은 도구 제한 함수를 연결했지만 이 환경에는 herdr 실행 파일이 없어 실제 어댑터 통합 시험을 완료하지 못했다. 실제 유료 Claude 모델 실행은 하지 않았다.

옵션 근거는 [Codex 설정 참조](https://developers.openai.com/codex/config-reference)와 [Claude CLI 참조](https://code.claude.com/docs/en/cli-reference)의 도구 가용성·MCP 제한 설명이다. 프롬프트의 역할 설명을 실행 권한 검증으로 대신하지 않는다.
