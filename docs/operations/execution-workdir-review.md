# 실행 위치 연결 수정의 검토 안내

이번 변경은 Codex의 로컬 파일 주소를 경로로 읽고, 검사마다 원 명령과 실제 도구 실행 위치를 따로 기록한다. 명령을 `cd` 셸문으로 합성하지 않는다.

범위는 작업 브랜치다. 메인 합치기·실제 서비스 반영·QA 재제출은 포함하지 않는다. 실제 God checker나 소설 입력을 실행하는 재현 명령은 이 문서에 없다.

## 파일별 변경 이유

| 파일 | 이유 |
| --- | --- |
| `server/harness-workdir.ts` | 로컬 file URI만 엄격하게 절대 경로로 푼다. 일반 절대 경로는 보존한다. |
| `server/harness-evidence.ts` | Codex cwd를 정규화하고 명시한 workdir 또는 기존 등록 위치로 대조한다. 미확인 cwd끼리의 일치를 거절한다. |
| `server/harness.ts` | 원 command와 별개의 선택 필드 workdir를 정의한다. |
| `server/agent-tools.ts` | 검사별 workdir의 절대 경로 입력을 검증하고 도구 스키마에 알린다. |
| `server/orchestrator.ts` | 원 workdir를 보존하고 지원 진단·업무 조회에 연결한다. |
| `server/store.ts` | 검사별 workdir를 그대로 기록하고 조회한다. |
| `server/db.ts` | v36에 nullable workdir 열을 추가한다. 과거 행은 NULL이다. |
| `server/harness-exec-diagnostics.ts` | 지원하는 CommandExecution의 위치를 같은 규칙으로 읽어 판정과 진단을 맞춘다. |
| `tests/harness-workdir*.test.ts` | 순수 판정 경계와 격리된 API·기록·진단을 검증한다. |

## 입력의 뜻

```json
{
  "kind": "behavior",
  "name": "합성 검사",
  "result": "pass",
  "command": "bun  test 'synthetic test.ts'",
  "workdir": "/fake/review results/한글%",
  "evidence": "도구의 cmd와 workdir를 각각 기록함"
}
```

command는 실제 도구에 전달한 문자열이다. 공백과 인용을 다듬지 않는다. workdir는 같은 호출의 절대 경로다. 생략한 기존 보고는 등록된 직원 위치를 기준으로 한다. 다른 실제 폴더는 거절한다.

로컬 호스트는 런타임 URL이 빈 호스트로 해석하는 localhost만 허용한다. 대문자 LOCALHOST도 같은 규칙이다. 루프백 IP·원격 호스트를 DNS 등으로 추정하지 않는다. 다른 스킴·상대 file:값·깨진 인코딩·NUL·query·fragment는 거절한다. 일반 절대 경로의 공백·한글·%는 원문 그대로 유지한다.

## 검토자가 실행할 최소 회귀

등록된 macOS Bun 런타임에서 다음 명령을 쓴다.

```sh
bun install --frozen-lockfile
IAMCEO_TEST=1 bun test tests/harness-workdir.test.ts tests/harness-workdir-integration.test.ts
bun run typecheck
```

실제 조사에서는 운영 릴리스가 사용한 Bun 1.3.14로 회귀를 실행했다. Bun 1.3의 fileURLToPath가 깨진 % 이스케이프를 그대로 둘 수 있어 별도 인코딩 검증도 넣었다.

관련 기존 회귀는 `IAMCEO_TEST=1 bun test harness`로 확인한다. 이 명령들은 가짜 제공자 기록·격리된 시험 DB를 쓴다. 직원 세션·실제 God 입력과 분리돼 있다. IAMCEO_TEST는 이 시험 명령에만 지정하며 기본 소켓 접근을 사전에 차단한다.

전체 회귀의 기존 시험은 `evidence/latest-main-20261117` 폴더를 미리 요구한다. 폴더 권한 거절 시험은 그 시험 프로세스의 umask가 022라는 조건도 가진다. 필요할 때만 해당 시험 명령 앞에 `umask 022`를 두며 개인 기본값은 바꾸지 않는다. 최초 전체 실행은 이 환경 조건 없이 종료 137로 끝났고 최종 집계를 내지 못했다. 관측한 실패와 이후 범위별 재확인 결과는 최종 자료에 빠짐없이 남긴다. 전체 회귀 통과를 주장하지 않는다.

## 원 다섯 항목의 대조

원 command·도구 workdir·CommandExecution의 id/argv/cwd/시각/개별 종료값만 메모리에서 추려 수정 전후의 순수 함수에 전달했다. 원 출력·소설 본문·전체 JSONL은 이 저장소에 넣지 않는다. 제한된 실제 대조 결과는 연결한 IAMCEO 자료에 둔다.

이 대조는 파서와 matcher의 연결만 확인한다. 원 거절 당시의 전체 내부 경로·다른 업무의 사용 여부·운영 전체 관문 통과는 입증하지 않는다. 합성 회귀와 실제 원 항목의 메타데이터를 혼동하지 않는다.

## 이 브랜치의 관측 결과

- 최초 새 회귀는 20 통과·33 실패였다. 주소 해석과 workdir 입력 경로의 실패를 먼저 확인했다.
- URI·유니코드 경계 보완과 v35 행 보존 검사를 포함한 최종 새 회귀는 67 통과·0 실패다.
- harness 관련 전체와 처음 환경 실패가 난 세 파일을 함께 확인한 범위는 414 통과·0 실패다.
- 시험 전용 IAMCEO_TEST와 umask를 지정해 기본 소켓 차단·홈 잠금·설정 파일의 기존 세 파일도 79 통과·0 실패로 확인했다. 개인 기본값이나 운영 차단 코드는 바꾸지 않았다.
- 최종 `bun run typecheck`는 종료 0이다.
- 실제 다섯 항목의 제한 대조는 수정 전 거절 5개, 수정 후 명령 변경 없이 연결 5개다. 위치 생략·다른 위치 지정은 각각 거절 5개다.
- 전체 회귀는 종료 137·최종 집계 없음이다. 범위 밖 화면 실패와 WebKit 부재는 해결한 것으로 쓰지 않는다.

## 독립 검토와 서비스 후속

이 구현자의 자기 검토는 독립 검토가 아니다. 검토자는 URI 거절 경계, 원 command 보존, workdir 생략의 호환성, 다른 실제 위치의 거절, 지원 진단의 일치, v35 행의 보존을 확인해야 한다.

작업 시작 때 운영은 e707d825 릴리스·스키마 v35였다. 마지막 읽기 전용 확인에서는 운영과 origin/main이 80d4d766으로 바뀌었고 server_check는 스키마 v37/지원 v37을 반환했다. 새 실행 파일의 실제 지문도 그 릴리스 기록과 같다. 이 구현자는 메인이나 서비스를 바꾸지 않았다.

이 브랜치는 dd8ead215를 기준으로 만들었으며 workdir 열을 v36에 추가한다. 새 메인은 v36을 task_stage_marks 등 업무 흐름에 쓰고 v37도 추가했다. 따라서 이 브랜치를 현재 서비스에 그대로 적용하거나 스키마 v36이 호환된다고 주장할 수 없다. 최신 메인과의 통합은 이 작업의 금지 범위라 실행하지 않았다.

후속 작업에서는 현재 메인의 v36·v37을 보존하고 workdir 이주를 그 뒤의 새 판(현재 기준 v38)에 붙여야 한다. 변경 함수·도구·저장 경로를 현재 소스에 연결하고 v37 기존 행 보존 및 관련 회귀·코드 검사를 다시 확인해야 한다. 이후 정확한 릴리스, 기존 운영 절차의 백업·스키마 전환, MCP 도구 스키마 갱신이 필요하다. 현재 서비스의 Codex cwd 수집은 여전히 원 file URI를 그대로 보관한다.

기존 직원·대기열을 보존하는 실제 서비스 절차는 별도 후속 범위다. 이 브랜치는 운영 DB를 열거나 전환하지 않았다. 위 67·414·79건은 이 브랜치의 고정 기준판에 대한 결과이며 새 메인 통합판의 통과가 아니다.

미적용 운영 코드가 이 직원의 시험 기록도 못 연결하면, 실제 시험 종료와 자동 완료 거절을 구분해 막힘으로 보고한다. 시험이나 완료 제출을 반복하지 않는다.
