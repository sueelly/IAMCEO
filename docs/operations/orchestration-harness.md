# 총괄의 조정·모니터링 전용 하네스

사용자의 2026-11-18 요구에 따라 총괄은 업무 정의·배정·예외 해결·상태 조회·비동기 최종 확인을 맡고, 직원은 완료 조건을 충족할 때까지 수행한다. 직원의 하네스 검사가 통과하면 후속 업무를 먼저 시작한다는 선택을 반영했다.

## 동작과 완료 기준

| 요구 | 구현과 판정 |
| --- | --- |
| R1. 총괄은 제작·구현을 직접 수행하지 않는다. | A1. 총괄의 서버 도구를 명시적 허용 목록으로 제한하고 CLI의 명령·파일 수정·네이티브 하위 에이전트 경로를 제거한다. 직원의 제작 권한은 유지한다. |
| R2. 배정 전에 입력·산출물·범위·제약·완료 조건·제외를 명시한다. | A2. 누락된 실행 계약은 배정과 실제 입력 전에 거절한다. 제약·제외의 빈 배열은 명시적 없음이며, 누락이나 공백은 미정이다. 옛 지시 원문과 계약 이력은 보존한다. |
| R3. 직원은 남은 조건을 이어 수행한다. | A3. 수행 가능한 업무의 다음 실행은 원 담당 직원에게 연결한다. 총괄이 다른 보고를 처리 중이어도 직원의 실행을 막지 않는다. |
| R4. 실패 반복·막힘·이상은 총괄이 해결한다. | A4. 같은 실패 세 번 또는 진척 없는 후속 요청은 총괄에게 한 번 연결한다. 총괄은 변경한 접근을 기록해 다시 열고 배정한다. 기존 대표 결재는 그대로 기다린다. |
| R5. 하네스 통과 후 후속 업무를 시작한다. | A5. 현재 계약의 실제 통과 근거와 차단 조건을 확인해 수행 완료를 기록한다. 상위 계약을 이어받은 하위 업무의 근거도 연결하며, 미승인 후보를 실행 의무로 편입하지 않는다. |
| R6. 최종 확인은 비동기로 진행한다. | A6. 수행 완료와 총괄 검수 상태를 따로 저장한다. 총괄은 `task_stage(done)`에 확인 근거를 남기거나 `reopen`으로 보완을 요청한다. 확인이 남으면 재시작 뒤에도 한 건의 알림으로 이어간다. |
| R7. 상태·대기열은 최신 근거를 반영한다. | A7. 계약 변경·정정 보고·새 차단 조건·하위 업무 재개가 자동 완료를 취소한다. 후속 전달 직전과 복구 재전송에서도 계약 판을 확인한다. |
| R8. 총괄은 필요한 직원을 배정하고 미사용 직원을 해제한다. | A8. 해제는 이력을 보존하는 휴면으로 처리한다. 실제 실행·백그라운드 작업·하위 에이전트·대기 입력·승인 창이 남아 있으면 해제를 거절한다. |
| R9. 총괄은 짧은 조정 턴과 즉답을 우선한다. | A9. 한 입력 묶음을 최대 세 건으로 제한한다. 긴급 입력과 대표 요청·개입을 우선하면서 오래된 보고에도 처리 기회를 남긴다. |
| R10. 기존 실행 보호를 유지한다. | A10. 대표 중단·승인 대기·한도·수신 불확실·세션 소유권을 우회하지 않는다. 지원 여부가 확인되지 않은 실행기에서는 총괄 입력을 보존한다. |

총괄 입력 묶음 세 건과 기존 후속 점검 간격 30초 재사용은 구현 선택이다. 사용자가 지정한 실패 반복 기준 세 번과 구분한다. 짧은 사실 질문은 총괄이 직접 답하고, 자료 작성이나 실행 검증은 직원에게 맡긴다.

담당 직원의 계약에는 해당 직원이 직접 수행하고 검증할 수 있는 결과를 적는다. 다른 담당자의 검토·통합·적용은 앞 단계의 산출물을 입력으로 받는 별도 업무로 연결한다. 상위 업무는 승인된 전체 결과를 추적한다.

직원은 계약 범위에서 고칠 수 있는 실패의 원인을 찾아 수정하고 다시 검사한다. 조건이 남은 채 실행을 마치면 진행 보고의 `continue_work: true`로 이어 할 행동을 기록한다. 이 진행은 실행 보고 의무만 마감한다. 같은 담당자가 재개할 수 있는 업무는 보고가 빠져도 다음 실행에서 남은 조건을 이어 간다. 외부 담당자의 결과나 추가 권한이 필요한 막힘은 총괄에게 전달하고, 같은 검사 실패는 실행마다 한 번씩 세어 세 번째에 총괄이 개입한다.
