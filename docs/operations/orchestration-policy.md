# 완료 기준, 반복 실패, 실행 상한

모든 실행 업무는 총괄 또는 대표가 확정한 완료 기준으로 판정한다. 기존 업무와 기타·조사 업무에도 적용한다. 예전 하네스 표시 설정과 생성 시점은 면제 조건이 아니다. 기준을 제안한 직원은 총괄 확인 전 그 제안으로 완료할 수 없다.

총괄은 입력·산출물·범위·제약·완료 조건·제외를 정의하고, 담당자를 배정하고, 예외를 해결하며, 상태를 종합한다. 제품 설계·구현·자료 제작·실행 검증·배포는 담당 직원에게 맡긴다. 이 역할 규칙은 사용자 정의 템플릿에도 붙는다. 서버 도구 허용 목록과 제공자별 네이티브 권한 제한을 함께 적용하며, 기존 대화는 보존하고 쉬는 시점에 같은 대화로 규칙을 갱신한다. 제공자별 검증 범위와 제한은 [총괄 실행 권한](conductor-role-policy.md)을 따른다.

완료 보고가 있어도 기준별 증거와 완료 조건이 남으면 직원의 후속 실행이 이어진다. 코드 업무는 통합·적용 근거까지 요구한다. 하네스가 현재 계약의 완료 조건과 차단 조건을 확인하면 수행 완료로 기록하고 후속 업무를 시작한다. 총괄의 최종 확인은 별도로 저장해 비동기로 진행한다. 총괄의 턴 종료나 막힘 보고만으로 완료하지 않는다. 대표가 중단한 일, 결재·승인 대기, 수신이 불확실한 입력과 계정 한도는 그대로 보존한다. 후보 등록은 실행 승인이 아니다.

같은 실패가 세 번 연속 보고되면 업무별 총괄 개입 알림을 한 번 생성한다. 알림에는 원인, 최근 시도, 남은 기준과 필요한 판단을 남긴다. 총괄의 종합 보고나 같은 보고의 재처리·정정은 새 실패로 세지 않는다. 총괄이 접근 변경 근거를 기록해 다시 열기 전에는 미리 쌓인 지시나 상위·파생 업무의 재배정으로 개입 대기를 우회하지 않는다. 이 경로에서 새 대표 결재를 자동 생성하지 않는다. 이미 존재하는 대표 결재는 보존하며 대표 답이나 해당 실패 이후 같은 업무 범위의 검증된 대표 원문이 있어야 재개할 수 있다.

2026-11-18 변경의 전체 요구·저장 경계·검증 결과는 [총괄의 조정·모니터링 전용 하네스](orchestration-harness.md)에 기록했다. 아래 검사 수는 이전 정책 구현의 기록이며 이번 변경의 검사 수나 운영 적용 영수증을 대신하지 않는다.

설정의 `전체 동시 실행`은 모든 프로젝트의 합계 상한이다. 프로젝트 편집의 `동시 실행`에서 전체 상한을 따르거나 1~64의 별도 상한을 지정한다. 실제 상한은 두 값 중 작은 값이다. 기본값은 전체 상한 따르기이며 기존 전체 설정은 바꾸지 않는다. 총괄의 자동 실행도 자리를 사용한다.

상한을 낮추면 현재 실행은 계속되고 새로운 입력부터 기다린다. 상한을 높이거나 전체 상한 따르기로 바꾸면 대기열을 다시 확인한다. 자리 예약, 저장된 실행, 실제 터미널 점유를 중복 없이 세고 실제 입력 쓰기 직전에도 검사한다. 한 프로젝트의 자리가 차도 다른 프로젝트는 남은 전체 자리에서 실행할 수 있다.

## 검증 기록

최신 업무 관리판과 통합한 관련 49개 검사 묶음 998건, PC·모바일 설정 및 업무 흐름 브라우저 검사 22건과 타입 검사가 통과했다. 실제 전송 직전 상한·결재·기준 변경, 기존 대기열, 이전 DB의 배정 영수증 보존을 포함한다. 독립 검토의 마지막 반례인 뒤늦은 대표 지시에 가려진 기준 요청도 재현 후 수정했다. 운영 반영 완료 영수증은 Git 밖의 작업 전용 private 경로에서 관리한다.

전체 시험의 저장 최적화 두 건과 보관 중 기존 입력의 사유 검사 한 건은 변경 전 `2f51d9b`에서도 동일하게 실패했다. 기존 전 과정 브라우저 시험은 격리 작업 폴더 밖의 경로를 사용하는 fixture에서 세션을 시작하지 못했다. 이를 우회하거나 전체 시험 통과로 보고하지 않는다.
