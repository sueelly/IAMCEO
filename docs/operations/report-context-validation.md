# IAMCEO 출력의 대상과 맥락 개선 검증

2026-11-18에 요청받은 작성 원칙 10가지를 공통 프롬프트와 자동 생성 보고에 적용했다. 대화·아티팩트·팀 상태·업무 보고·결재 요청에서 업무명, 요청한 결과, 확인한 범위와 근거, 남은 조건, 다음 행동의 주체와 대상을 보존하는 변경이다.

이 문서는 작업 브랜치의 구현·검증 기록이다. 운영 배포나 기존 보고의 수정 완료를 뜻하지 않는다. 실제 직원 실행·결재 응답·운영 데이터 변경은 수행하지 않았다.

## 무엇을 바꿨는가

- `server/roles/writing.md`에 사용자 원칙과 통로별 작성 지침을 기록했다. 문장·제목·보고의 일률적인 길이 제한과 근거 식별자 금지를 제거했다. 배포·재시작·검증을 같은 말로 치환하지 않도록 했다.
- 기본 역할, 사용자 정의 역할, 이전에 내보낸 역할에 최신 공통 지침이 전달되도록 했다. 새 세션과 재개 세션의 규칙 파일 재생성도 확인했다.
- 팀 상태·보고·결재·자료 도구의 설명과 비차단 글 검사 경고를 맞췄다. 경고는 직원에게 반환하며 저장할 보고 원문을 고치거나 접수를 거절하지 않는다.
- 자동 후속 조정 결재와 반복 막힘 결재에 같은 업무의 요청 원문·시각·완료 기준·최근 보고·검사 기록을 포함했다. 제안한 기준, 검사 미실행, 실패, 기록 부재를 구분한다. 다른 업무의 기록은 연결하지 않는다.
- 완료 알림에서 근거의 커밋·기록 식별자를 지우거나 빈 근거를 ‘확인함’으로 대체하던 처리를 제거했다. 승인·재전송·완료 판정 조건은 바꾸지 않았다.

## 전체 검사에서 남은 문제

`bun test tests`는 전체 통과하지 않았다. 저장소 이주 검사와 기존 가짜 CLI 화면 검사의 실패를 확인했고, 후속 화면 검사가 연쇄 실패하는 실행을 중단했다(종료 코드 143). 중단한 프로세스는 이 작업 워크트리에서 시작한 검사와 그 자식 프로세스로 한정했다. 따라서 전체 검사가 끝났거나 모든 실패 원인을 규명했다고 보고하지 않는다.

기준 커밋 `5140c3936ad990f90dfcbe8ddc7212ab94370ab2`의 별도 워크트리에서도 다음 실패를 재현했다.

- `storage-maintenance-optimization.test.ts`: 이주 전후 논리 데이터 불일치 2건. 기준 버전 결과는 4개 통과·2개 실패다.
- `e2e-fake.browser.ts`: 초기 직원 등록과 컴파일 서버 실행 2건. 기준 버전에서도 직원 등록 대기 시간 초과와 `Path is outside this fixture`가 발생했다.
- `tools.test.ts`: 기존 계약 조건·대기 관련 실패 15건과 오류 1건. 이번 변경의 경고 관련 도구 검사는 별도로 3건 통과했다.
