# 웹 조회와 업무 점검의 서버 비용

프로젝트를 열거나 직원 대기열을 확인할 때, 한 번 읽은 업무 근거와 이미 전달된 지시를 반복해서 처리하는 비용을 줄인다. 적용 대상은 IAMCEO의 기존 웹 조회와 서버 점검 경로다.

| 요구사항 | 완료 조건 |
| --- | --- |
| R1. 서버는 한 프로젝트의 상태 응답에서 업무 목록과 팀 배정도를 같은 진행 근거로 만든다. | A1. 업무가 있는 프로젝트의 일반·간략 상태를 각각 한 번 읽으면 전체 진행 근거 조회가 한 번이다. 새 결재를 저장한 다음 응답은 바뀐 단계를 반영한다. |
| R2. 후속 점검은 실행 기준이나 선행 업무를 확인할 때 대기 중인 지시만 상세 조회한다. | A2. 전달 이력이 늘어도 완료된 전달의 본문 조회는 0회다. 앞선 대기 지시 뒤에 이미 전달된 지시가 있어도 계약 확인 대상을 유지한다. |
| R3. 서버는 대기열을 점검할 직원의 ID만 조회한다. | A3. 전역·프로젝트별 조회에서 기존 수신 순서와 중복 제거 결과가 일치한다. 주기 점검과 복구의 보류 처리 차이를 보존하고 수신자 조회에서 전달 본문을 가져오지 않는다. |
| R4. 직원에게 전달할 항목이 실제 업무에 연결될 때 순서 검사를 시작한다. | A4. 업무 없는 직원 알림은 발송 직전까지 프로젝트 업무 순서를 조회하지 않는다. 연결된 지시에서는 선행 업무·중단·승인 상태가 바뀌면 실제 전송을 차단한다. |

각 항목은 격리 데이터에서 먼저 비용 초과를 재현하고, 변경 뒤 같은 검사에 기존 기능 검사를 더해 확인한다. 조회 결과는 한 요청이나 동기 판정 안에서만 재사용한다. 운영 연결 끊김의 빈도와 프로세스 분리의 효과는 별도 검증 대상이다.
