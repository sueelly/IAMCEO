# 임시 공동 총괄 운영

대표가 특정 프로젝트의 검수 병목을 해소하도록 지시한 경우, 기존 총괄을 유지하면서 임시 공동 총괄 한 명을 추가할 수 있다. 일반 직원의 이름만 바꾸는 방식과 달리 임시 세션은 `conductor` 권한으로 계약 확인·검토 배정·업무 단계 판정을 수행한다. 기본 보고 수신자와 `getConductor`는 원래 총괄을 유지한다. 일반 직원 수에는 포함하지 않는다.

## 생성과 인계

대표 인증을 사용하는 `POST /api/projects/:id/temporary-conductor`에 다음 값을 보낸다. 직원용 도구나 일반 직원 생성 API에는 추가 권한을 노출하지 않는다.

```json
{
  "name": "임시 검수 공동 총괄",
  "role": "고정한 검수 대기 목록과 그 재검수를 처리하고 원래 총괄에게 인계한 뒤 종료한다.",
  "sourceMessageId": "대표가 지시한 메시지 ID",
  "taskId": "그 대표 메시지의 업무 ID",
  "modelOverride": "gpt-6-astra",
  "effortOverride": "xhigh",
  "parallel": true
}
```

서버는 같은 프로젝트의 대표 글·업무, 기존 총괄, 추가 총괄 수를 확인한다. 같은 글과 업무로 재요청하면 생성 중인 기존 세션을 반환한다. 종료한 요청은 영속 종료 기록으로 재생성을 거절한다. 검증된 안전한 종료를 지원하는 core 실행기에서만 사용할 수 있다. Fast는 모델의 effort와 별개이므로 실제 CLI 화면에서 `Fast`를 확인한다.

인계물은 Git 밖의 작업 전용 0700 폴더와 0600 파일로 보존한다. 프로젝트 메시지·업무·계약·단계·결정·자료와 원본 총괄의 native 기록을 개수·해시·시점과 함께 묶는다. 인증 값은 제거하며 확보할 수 없는 자료와 해독할 수 없는 요약은 명시한다. 전체 기록을 읽을 수 있게 제공하는 것과 전체 기록이 모델의 유한한 문맥 창에 동시에 들어갔다는 주장을 구분한다.

원래 총괄은 처음 넘길 검수 목록과 기존 검토자·작성자·판정 소유자를 고정한다. 임시 총괄은 이미 맡긴 독립 검토를 중복 배정하지 않고 해당 보고를 판정한다. 후보 인덱스는 확정 대기 목록을 대신하지 않는다. 제품 수정·메인 통합·서비스 변경·승인 응답은 기존 업무의 승인 범위를 따른다.

고정 목록의 원업무에는 장기 제품 업무가 포함될 수 있다. 종료 기준은 그 제품 전체의 완료가 아니라, 원업무별로 맡긴 이번 검수의 실제 판정·근거·후속 소유권 인계와 필요한 재검수의 완료다. 검수 결과를 원제품 전체 완료로 바꾸지 않는다. 해결되지 않은 검수 조건을 검수 완료로 표시해서도 안 된다.

## 검수 종료와 제거

`scripts/temporary_conductor_watch.py`는 모델을 호출하지 않는 일회 점검기다. 작업 전용 스케줄러에서 호출하면 대기열을 읽어 확인하며 다음 조건을 모두 만족한 뒤에만 안전한 종료 API를 호출한다.

- 고정한 모든 원업무에 대응하는 별도의 검수 업무가 있고, 그 업무는 이번 임시 총괄 업무의 하위 작업이며 실제 `done`이다.
- 이번 업무 아래 생긴 추가 수정·재검수·인계 작업도 모두 실제 `done`이다.
- 임시 총괄의 최종 보고에는 코드 블록·인용문 밖의 독립된 줄에 `TEMP_REVIEW_DRAINED:<taskId>`가 있다.
- 원래 총괄은 그 최종 보고를 `about_report_id`로 가리켜 보고하고, 독립된 줄에 `TEMP_REVIEW_HANDOFF_ACCEPTED:<taskId>`를 남긴다. 서버의 `aboutMessageId`, 작성자와 시각을 대조한다.
- 임시 세션이 쉬고 있고 미전달·불확실 입력, 진행 실행, 열린 결정이 없다.

설정 파일에는 `home`, `projectId`, `memberId`, `primaryMemberId`, `taskId`, `sourceMessageId`, `backlogTaskIds`, `ledgerPath`를 둔다. 접속 코드는 복사하지 않고 기존 운영 설정에서 메모리로만 읽는다. `backlogTaskIds`는 원래 총괄의 확정 목록으로 고정한다. ledger는 다음 구조이며 후보 목록이나 임의의 완료 업무로 대체하면 안 된다.

```json
{
  "projectId": "프로젝트 ID",
  "memberId": "임시 총괄 ID",
  "taskId": "임시 총괄 업무 ID",
  "reviews": [{"backlogTaskId": "원업무 ID", "reviewTaskId": "검수 업무 ID"}],
  "finalReportId": "임시 총괄의 최종 보고 ID",
  "primaryAckReportId": "원래 총괄의 인계 수신 확인 보고 ID"
}
```

```sh
python3 scripts/temporary_conductor_watch.py --config /absolute/private/path/watch.json
python3 -B tests/temporary-conductor-watch.test.py
```

종료는 `POST /api/projects/:id/temporary-conductor/:member/retire`에 원래 `sourceMessageId`와 `taskId`를 보내 수행한다. 서버가 다시 유휴·전달·결정·압축·세션 상태를 검사하고 정식 idle-only 종료를 사용한다. 검사를 통과한 뒤 새 입력이나 결정이 들어와도 명부와 해당 상태를 지운 채 성공하지 않는다. 일반 강제 닫기 경로는 사용하지 않는다.

점검기는 종료 요청 의도를 원자적으로 먼저 저장한다. 전송 결과가 불확실하면 같은 종료 요청을 자동으로 재생하지 않고 조회만 한다. 원래 총괄은 유지하며 보고·자료·업무 이력은 보존한다. 이 점검기는 업무 완료 판정·승인 응답·입력 재전송을 수행하지 않는다.

## 검증 기록

새 생성·권한·종료 검사 31건, core 실행기·업무 배정까지 포함한 집중 검사 198건과 종료 점검기 검사 15건이 통과했다. 타입 검사와 컴파일도 통과했다. 독립 검토에서 확인한 비-core 종료, 종료 뒤 재생성, 잘못 연결된 인계 확인, 목록에 빠진 파생 검수는 실패 반례를 보완한 뒤 통과했다.

확장 회귀는 267건 통과·3건 실패다. `@직원 직접` 보고의 두 경로와 직접 CLI `wait` 답 묶기 실패는 변경 전 `49df056`에서도 같은 조건으로 재현됐다. 별도 기준판 검사에서도 저장 최적화의 내용 해시 두 건과 HTTP capabilities 기대값 한 건이 실패했다. 전체 검사는 가짜 CLI 브라우저 fixture의 `Path is outside this fixture` 오류와 연쇄 실패 뒤 완료하지 못했다. 소유한 검사 프로세스만 종료했다. 전체 검사 통과나 운영 반영 완료를 뜻하지 않는다.
