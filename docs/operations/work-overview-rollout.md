# 업무 관리판 main 통합과 운영 반영

2026-11-18 사용자가 작업 브랜치의 main 병합과 운영 서비스 반영을 승인했다. 구현 워크트리 `work-overview-01a1ea05`에서 최신 origin/main을 통합하며 다른 작업자의 기본 체크아웃과 미커밋 변경은 수정하지 않는다.

완료 조건은 통합 회귀·타입 검사·컴파일 통과, 작업 브랜치와 main 일반 푸시, 정확한 원격 main SHA의 릴리스, 로컬 및 기존 Tailscale 주소에서 새 build ID와 업무 관리판 확인이다. 실제 업무 배정이나 승인 응답은 배포 검증에 사용하지 않는다.

통합 시 이미 운영된 v38 후속 실행 이주를 그대로 두고 업무 배정 영수증을 v39로 추가한다. 기존 후속 실행의 중단·담당 추정 정책을 배정 API도 지켜야 한다. v38 이주와 원래 중단 상태 보존, 파생 업무 중단 우회 거절, 보고·진행판에서 담당이 확인된 업무의 중복 배정 거절을 검사한다.

보고·진행판의 담당 추정은 실제 실행 대기열의 순서와 현재 위치를 바꾸지 않는다. 배정 미리보기는 같은 화면 투영을 사용해 완료되지 않은 업무의 위치를 계산한다. 추정된 부모의 파생 업무가 실제 선행 업무인 경우에도 화면과 실행 판정이 일치하는지 검사한다.

배포 전 기존 plist·설정·SQLite 일관 백업과 core 터미널 PID·대화 세대를 private 경로에 보존한다. 검증한 바이너리로 `com.iamceo.server`의 웹 서비스만 정상 재시작한다. core 서비스와 직원 프로세스는 종료하지 않는다. 대화·승인·업무 자료의 기존 ID와 직원 세대를 배포 후 대조한다. 자연스럽게 끝난 턴과 앱의 정상적인 idle 세션 갱신은 근거와 함께 구분한다.

기존 Tailscale 경로와 인증 설정을 유지한다. 새 바이너리 확인에 실패하면 서비스를 점검하며 운영 DB를 과거 백업으로 자동 교체하지 않는다. 새 버전에서 추가된 쓰기가 있을 수 있으므로 DB 복구는 별도 판단이 필요하다.

실제 배포 영수증과 백업은 Git 밖 `.runtime/IAMCEO/private/work-overview-rollout-20261118-01a1ea05/`에 둔다. 이 절차 문서 자체는 배포 성공 영수증이 아니다.
