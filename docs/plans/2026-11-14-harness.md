## 코드에 드러나지 않는 결정

1. 계약은 업무(task)에 붙는다. 직원이 아니라 업무가 단위라, 같은 업무를 여러 직원이 다뤄도 계약 판(rev)은 하나다. 검사 기록은 글·직원·실행·계약 판을 함께 남겨 책임이 섞이지 않는다.
2. 계약이 있는 업무만 완료 판정을 건다. 계약 없는 옛 업무·대표 직접 일은 지금처럼 둔다(되돌리기 없이 켤 수 있게). 총괄 역할 글이 맡길 때 계약을 쓰게 한다.
3. 완료 판정은 서버가 한다: 필수 검사 종류마다 통과 1건, 실패 0건, 합격 기준마다 그 기준을 가리키는 통과 검사 1건. 막히면 `완료`를 거절하고 `막힘`은 받는다. 서버는 검사 명령이 실제로 돌았는지 실행 기록과 대조하지 않는다(자기 보고). 후속(아래)에서 실행 검사는 제공자 기록 대조로 바꿨다.
4. 실행 차단은 Claude 직원에만 건다. IAMCEO가 띄울 때 넘기는 `--settings`의 PreToolUse 훅이다(전역 설정은 안 바꿈). 권한 확인 건너뛰기 방식에서도 훅 거절이 실제로 막는 것을 2.1.323으로 확인했다. Codex(0.167)·Antigravity(1.5.8)는 훅·규칙을 이번에 검증하지 않아 걸지 않는다.
5. 훅은 명령 글자와 파일 경로만 본다(셸 전체를 통제하지 않는다). 지우기·깃허브 올리기·gh 쓰기 하위 명령·패키지 공개는 '묻기'(대표 승인 창), 비밀 파일·IAMCEO 데이터 폴더는 '거절'이다. curl·wget 같은 다른 네트워크 도구, 외부 MCP 도구, 다른 프로그램 안에서 지우는 일(예: 스크립트 안의 삭제)은 막지 못한다. 훅이 죽으면 막지 않는다(일이 멈추지 않게).
6. 재개 때 대화 전량을 넘기지 않는다. 지시에 계약 판, 원문 참조, 그 업무의 최근 검사 결과(보고 id), 열린 결재만 싣는다.
7. 기억은 지금 Hindsight 계약을 그대로 쓴다. 새 기억 DB·전량 전송 없음.

## 독립 검토 1차 반영 (검토: 엘리트사원 클로드, 기준 8c7bf66)

- 계약 우회: 직원이 이번 턴에 계약 있는 업무를 받았으면, 받지 않은 계약 없는 업무(새로 만든 업무·자기 계약 업무 포함)로 `완료`를 올리지 못한다. 받은 업무끼리는 각자 판정한다. 갈래 업무는 위 업무의 계약을 따르고(`getEffectiveContract`), 직원은 갈래에 계약을 덮지 못한다.
- 판 번호: `post.contract_rev` 로 검사가 따른 판을 밝힌다. 없거나 지금 판과 다르면 `완료`를 거절하고 새 판 기준을 거절 글에 싣는다. `report_harness.contract_task_id`·`contract_rev` 에 따른 계약을 남긴다.
- 훅: 셸 낱말을 풀어(따옴표·이스케이프·$( )·백틱·bash -c·eval·xargs·find -exec·here-doc) 명령 자리만 본다. rm 옵션 순서·경로(/bin/rm, \rm)·git 전역 옵션(-C·-c)·작업 중 변경을 버리는 restore/checkout/switch 를 묻는다. 따옴표 안 설명문은 막지 않는다. 경로는 글자 일부가 아니라 경로 경계로 본다.
- 비밀: IAMCEO 데이터 폴더 전체(DB·백업·직원 토큰·접속 코드)를 거절한다. 대표 첨부(inbox)·역할 글(roles)만 연다. 그 폴더를 품은 상위 폴더의 통째 검색·복사도 거절한다. 영향: Claude 직원은 운영 DB 를 sqlite 로 직접 읽지 못한다.
- 작은 것: 실행 안 함이 섞인 완료 거절, 계약 작성자를 직원 id 로 가름, 직원 작성 계약 표시.
- 남김(이유는 결과 자료): 직원이 자기 계약을 느슨하게 고치기, 훅 고장 때 막지 않음, 계약 없는 업무는 판정 밖, 검사는 자기 보고, curl·외부 MCP, Codex·Antigravity.

## 후속: 기본 적용·실행 증거·제공자 제한 (feat/harness-defaults, 기준 0478398)

- 0478398(검토받은 판)은 그대로 두고, 이 후속은 DB v32 로 따로 올린다(v31 은 손대지 않는다). 두 판을 따로 합칠 수 있다.
- 기본 적용: 설정 `harnessMode` 기본 `label` 은 계약 없는 완료를 받되 '계약 없는 완료'로 기록·표시한다. `required` 로 바꾸면 그 시각(`harnessRequiredSince`) 뒤에 만든 업무만 확인된 계약이 있어야 직원·총괄 완료를 받는다. 옛 업무는 표시만 한다. 본사는 업무를 쓰지 않아 예외다. 서버가 뜻 없는 기본 계약을 붙이지 않는다.
- 직원이 단 계약은 '확인 전'이며 판정에 묶이지 않는다. 서버가 총괄에게 확인 요청(전 판과 기준 수·필수 검사 비교 포함)을 보내고, 총괄이 `confirm_contract_rev` 로 지금 판을 확인해야 묶인다. 고친 판은 다시 확인이 필요하다.
- 실행 증거: 실행 검사(behavior·typecheck·regression)의 통과는 직원 세션의 제공자 기록(Claude 세션 기록의 Bash tool_use↔tool_result, Codex rollout 의 CommandExecution)에서 계약 시각 뒤 그 명령의 마지막 실행이 종료 0 이어야 받는다. 명령 자리에서만 찾고(echo 안 글은 아님), 뒤에 | ; || & 가 붙으면 종료 코드가 그 명령 것이 아니라 거절한다(pipefail 은 받음). 실행 표지는 한 업무의 증거로만 쓴다. 기록을 못 찾으면 거절(막힘으로 올린다). Antigravity 는 실행 기록 형식을 몰라 '미지원'으로 남기고 개선 후보에 적는다.
- 조사: `claims` 의 사실 주장은 출처와 원문 인용이 직원이 계약 뒤 본 도구 결과(그 도구 인자에 출처가 있고, 인자에 인용이 이미 있지 않은 것) 또는 대표·다른 직원 자료 본문에 있어야 한다. WebFetch 는 요약이라 '요약에서'로 남긴다.
- 서버 소유 도구: `server_check`(판·DB 판·하네스 방식·최근 백업 manifest·마지막 백업 오류·실행 기록 대조 가능 여부, 경로 없음), `server_backup`(서버의 BackupManager 로 백업·검증, 10분 안 백업이 있으면 그것을 돌려줌). 직원은 데이터 폴더를 직접 읽지 않는다.
- 개선 후보 `harness_findings`: 완료 차단·증거 없음·증거 미지원·대표 직접 개입·대표 거절(글자 추정). 기록일 뿐 규칙을 바꾸지 않는다. 총괄이 되풀이되는 것만 개발 기억에 남긴다. `task_trace` 는 업무 한 건의 시작→보고 사슬을 읽기만 한다.
