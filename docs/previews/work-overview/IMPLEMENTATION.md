# 업무 관리판 구현·검증 기록

2026-11-18, 승인된 화면 구조를 IAMCEO의 기존 Glass·GlassButton·Modal/Sheet와 공통 색상·카드 토큰으로 구현했다. 모든 실행과 검증은 맥미니의 별도 워크트리에서 수행했다. 화면 이미지는 격리된 서버의 예시 데이터이며 운영 업무의 상태를 뜻하지 않는다.

## 구현한 동작

| 목적 | 실제 동작 |
| --- | --- |
| 지금 무엇을 하는지 비교한다. | 직원별 행에 최근 완료·지금·다음을 고정한다. 미완료 옛 기록과 막힘은 지금에 남긴다. 완료 이력만 최근 3개로 접고 완료 근거의 시각을 표시한다. |
| 같은 업무를 중복 집계하지 않는다. | 전체와 상태별 수는 업무 ID로 계산한다. 여러 담당의 노드는 각각 보여 주되 전체 업무 수는 한 번 센다. |
| 관계를 좁혀 본다. | 노드 우클릭 또는 메뉴로 같은 업무의 담당 노드와 직접 선행·후행·부모·파생 업무를 남긴다. 파생 업무 묶음은 순환을 막으며 범위를 넓힌다. 전체 보기에서 필터·스크롤·선택을 복원한다. |
| 맥락을 보존하며 배정한다. | 미배정 업무를 직원의 다음 칸에 드래그하거나 메뉴에서 담당자를 고른다. 검토 창에서 원래 지시, 확정 계약, 완료 조건, 필수 검사, 금지 사항, 근거, 최근 보고, 별도 저장된 실패 검사·정정 연결, 자료·첨부와 작업 위치를 확인한다. |
| 확정한 범위로 한 번 전달한다. | 확정 순간 계약·직원 세대·큐·보호 상태를 다시 확인한다. 전달·감사 기록·영수증을 하나의 트랜잭션에 저장한다. 응답을 잃으면 영수증을 조회한다. |
| 모바일과 키보드로 조작한다. | 좁은 화면에서는 지금·다음·최근 완료 순으로 세로 배치한다. 메뉴로 배정할 수 있고 Shift+F10으로 연결 집중을 연다. 상세를 닫으면 원래 카드로 초점이 돌아온다. |

이번 배정 범위는 **확정된 계약이 있는 미배정 업무를 직원의 다음 큐에 추가하는 것**이다. 이미 배정됐거나 실행 중인 업무의 담당 변경과 큐 재정렬은 포함하지 않는다. 미확정 계약·중단 보호·반복 감시·승인 대기와 수신 불확실 상태는 기존 조건을 유지한다. 대상 직원의 최근 관측이나 세션 소유권을 확인할 수 없으면 배정하지 않는다. 파생 업무와 총괄의 시작 조건은 실제 실행 정책에 맞춰 검토 창에 표시한다. 이 화면 변경은 자동 반복 실행 정책의 변경이나 개별 운영 업무의 완수를 뜻하지 않는다.

## 같은 내용을 텍스트로 보기

전체 화면을 캡처한 시점에는 직원 4명과 고유 업무 7개가 있다. 상단은 확인 필요 3개, 실행 중 0개, 다음 1개, 완료 1개, 미배정 2개를 표시한다. 예시 서버의 실행기는 외부 모델을 호출하지 않는다.

| 직원 | 최근 완료 | 지금 | 다음 |
| --- | --- | --- | --- |
| 총괄 | 없음 | 없음 | 없음 |
| 네이티브·Codex | 단계 표시 초안: 예시 완료 시각 01:04 | 완료·중단 보호 보완: 중단 뒤 입력이 남는 실패 근거가 있다. 오래된 업무 복구: 전달 대기 중인 현재 순서다. | 검증 근거 정리 |
| 하네스 검토 | 없음 | 보호 보완 재검증: 실행 턴이 끝났어도 업무 완료 확인이 남아 있다. | 없음 |
| 웹 담당 | 없음 | 없음 | 없음 |

미배정에는 ‘업무 연결 집중 보기’와 ‘자동 반복 실행 후보’가 있다. 앞의 업무는 확정 계약과 ‘승인 자동 응답 금지’ 조건을 갖고 있다. 뒤의 후보는 목표·완료 조건이 확정되지 않아 검토 창에서 배정이 막힌다.

‘완료·중단 보호 보완’과 ‘보호 보완 재검증’은 부모·파생 관계다. 우클릭 화면은 연결된 노드만 남긴다. 배정 검토 화면은 ‘업무 연결 집중 보기’를 ‘웹 담당’에게 넘기기 전이다. 모바일 이미지는 배정·응답 유실 검사를 실행한 뒤 캡처하므로 초기 화면과 개수가 다르다. 이 시점 차이를 운영 진척으로 해석하지 않는다.

- 관련 서버 검사: workflow·계약 하네스·업무 단계·HTTP·DB 마이그레이션·웹 동기화 25개 파일, 480개 통과.

- `bun run typecheck`, `bun run build`, `git diff --check` 통과.
- 기존 독립 설계 예시의 오프라인 검사 12개는 제품 검사와 별개다.
- 전체 저장소의 모든 검사를 실행했다는 뜻이 아니다. 독립 검토에서 발견한 배정 순서·실패 근거·직원 상태 검증을 보완한 뒤 위 검사를 다시 통과했다.
- main 병합, 운영 배포, 실제 직원 실행, 원래 세션이나 운영 데이터 변경은 수행하지 않았다.
