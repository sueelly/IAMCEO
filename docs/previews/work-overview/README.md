# 직원별 업무 흐름 예시

직원을 행으로, **최근 완료 → 지금 → 다음**을 고정된 열로 두는 화면을 제안한다. 누구의 일이 막혔고 다음 차례가 누구인지 같은 위치에서 비교한다. 미배정 업무는 오른쪽 대기열에 둔다.

이 파일과 `index.html`은 2026-11-18 설계 검토용 예시다. 업무 13개, 직원 4명, 상태·시각·계약 판은 가상 데이터다. 인용된 실제 문제를 이해하기 위한 시나리오이며 운영 상태를 조회한 화면이 아니다. 기존 업무나 직원에게 명령을 보내지 않는다. 배정은 열린 브라우저 메모리 안에서만 바뀌고 새로고침하면 초기 예시로 돌아간다.

사용자가 설계를 승인한 뒤 별도 작업 브랜치에 제품을 구현했다. 기존 Glass 구성요소를 사용한 [실제 구현 화면](product.html)과 [구현·검증 기록](IMPLEMENTATION.md)을 별도로 제공한다. main 병합과 운영 배포는 수행하지 않았다.

## 화면에서 확인할 것

- **막힌 일은 지금에 남는다.** 완료·중단 보호 보완은 옛 기록이어도 완료 근거가 없으므로 완료 이력으로 접지 않는다.
- **다음 업무는 순서와 시작 조건을 보여 준다.** 담당자를 정한 것과 실제로 시작한 것을 구분한다.
- **노드를 우클릭하면 관련 업무만 남는다.** 직접 선행·후행과 부모·파생 관계를 보여 주고, ‘업무 묶음’으로 범위를 넓힌다. ‘전체 보기’는 원래 필터와 스크롤을 복원한다. 카드의 더보기 메뉴에서도 같은 조작을 할 수 있다.
- **미배정 카드를 다음 칸으로 끌어 놓으면 인계 내용을 먼저 확인한다.** 원래 지시·완료 조건·관련 자료·제약을 확인하고 ‘배정’을 누르면 예시의 다음 대기열로 이동한다. 취소하면 이동하지 않는다. 실행 승인이 없는 후보는 배정할 수 없다.
- **드래그 없이도 배정할 수 있다.** 더보기 → 배정 → 담당 직원 선택 → 인계 확인 순서로 같은 화면을 연다.

직접 조작하려면 ‘업무 연결 집중 보기’를 ‘웹 담당’의 다음 칸으로 끌어 놓는다. 연결 집중은 ‘완료·중단 보호 보완’을 우클릭하면 다섯 업무만 남는 것으로 확인할 수 있다. 키보드는 더보기 버튼 또는 Shift+F10을 사용할 수 있다. Escape는 열린 상세와 인계 창을 닫는다.

## 화면과 같은 텍스트 현황

전체 고유 업무 13개 중 조치 필요 2개, 실행 중 2개, 배정된 다음 업무 3개, 완료 3개, 미배정 3개다. 미배정 중 2개는 배정 가능하고 1개는 요구사항 확인이 필요하다. 상단 집계는 집중 보기에서도 전체 수를 유지한다.

| 담당 | 최근 완료 | 지금 | 다음 |
| --- | --- | --- | --- |
| 총괄 | 업무 기준 정리. 완료 조건과 검토 범위를 확정했다. 18:10 완료. | 업무 단계판 통합. 19:43 검토 대기. 네이티브 담당이 보완 3건을 확인한 뒤 총괄이 재검토한다. | 메인 통합·적용 확인. 단계판 보완과 검토가 끝나면 시작한다. |
| 네이티브·Codex | 단계 표시 초안. 초안 작성 범위의 검증을 완료했다. 18:42 완료. | 완료·중단 보호 보완. 19:44 보완 필요. 미적용 완료 표시와 남은 입력을 수정해야 한다. 옛 기록이어도 완료되지 않았다. | 오래된 업무 복구. 보호 보완을 마친 뒤 이어서 수행한다. |
| 하네스 검토 | 예시에 완료 기록이 없다. | 보호 보완 재검증. 19:52 실행 중. 예시의 완료 조건 8개 중 5개를 확인했다. | 반영 후 회귀 검사. 메인 통합과 서비스 반영을 기다린다. |
| 웹 담당 | 대화 자료 연결. 파일과 원문 연결을 확인했다. 19:05 완료. | 업무 카드 정보 정리. 19:50 실행 중. 현재 상태와 다음 행동을 정리한다. | 아직 배정된 다음 업무가 없다. |

미배정 업무는 다음과 같다.

| 업무 | 상태 | 범위 |
| --- | --- | --- |
| 업무 연결 집중 보기 | 배정 가능. 예시 계약 r3. | 우클릭으로 직접 연결 업무를 표시하고 전체 보기에서 복원한다. 터치·키보드도 지원한다. |
| 미배정 목록 정리 | 배정 가능. 예시 계약 r1. | 미배정 사유와 다음 확인 담당자를 표시하며 같은 업무를 중복 집계하지 않는다. |
| 자동 반복 실행 정책 | 요구사항 확인. | 실행 범위·재시도 조건·실행 승인이 미정이므로 배정하지 않는다. |

실선은 같은 직원의 업무 순서다. 점선 파생 관계는 `업무 단계판 통합 → 완료·중단 보호 보완 → 보호 보완 재검증`, `메인 통합·적용 확인 → 반영 후 회귀 검사`다. 파생 관계 자체가 선행 실행 조건은 아니다.

## 실제 구현에 적용할 배정 규칙

첫 구현은 미배정이며 실행이 승인된 업무를 직원의 다음 업무로 배정하는 범위다. 실행 중인 업무의 담당 변경과 이미 배정된 큐의 재정렬은 별도 확장이다.

인계에는 같은 업무 ID, 원문과 시각, 확정 계약의 판, 완료 조건, 기존 보고와 실패 근거, 관련 자료·첨부, 작업 브랜치·워크트리, 금지 사항과 기존 승인·선행 조건을 연결한다. 서버는 드롭 후 확인 시점에 계약·담당·큐의 판을 다시 검사하고 operation ID로 중복 배정을 막아야 한다. 승인이 필요한 후보, 수신 여부가 불확실한 입력, 중단 보호와 반복 감시는 배정으로 우회하지 않는다.

HTML은 위 구조의 조작 예시다. 실제 서버의 원자성·권한 검사·동시 기기 충돌·중복 전달 방지나 컨텍스트 수신을 검증한 것은 아니다. 제품 구현의 요구사항과 완료 조건은 [상세 설계](../../superpowers/specs/2026-11-18-work-overview-design.md)에 있다.

## 검증 범위

`verify.mjs`는 기존 Playwright를 사용하며 IAMCEO 서버·직원·운영 DB를 시작하지 않는다. 오프라인 Chromium에서 12개 시나리오를 검사한다. 1440px·1600px 화면 정렬, 390px 모바일 넘침, 옛 막힘 기록 유지, 우클릭·범위 확장·복원, 실제 드래그의 대상 직원, 취소 무변경, 배정 1회, 미승인 후보 거절, 키보드·메뉴 대체, 새로고침 초기화, JavaScript 오류·외부 요청 0건을 확인한다.

```sh
cd '/Users/hyejookim/Programming/01_Ing/.worktrees/IAMCEO/work-overview-01a1ea05'
IAMCEO_VERIFY_DEPENDENCIES=/Users/hyejookim/Programming/01_Ing/IAMCEO node docs/previews/work-overview/verify.mjs
```

별도 설계 검토에서 구현 계획을 막는 중요한 미정 사항은 없다는 결과를 받았고, 사용자가 화면 구조와 디자인 시스템에 맞춘 구현을 승인했다. 이 문서의 12개 검사는 설계 예시의 검사다. 제품의 회귀 검사와 운영 반영 상태는 별도 구현 기록에서 확인한다.

작업 워크트리는 `/Users/hyejookim/Programming/01_Ing/.worktrees/IAMCEO/work-overview-01a1ea05`이며 브랜치는 `design-show-work-overview-01a1ea05`다. 원래 터미널의 변경과 독립적으로 만들었다.
