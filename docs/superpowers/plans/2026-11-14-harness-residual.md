판단:
- F1은 단독 함수 변경 문제가 아니라 호출자가 데이터를 변형한 문제다. 일반 문장용 cleanText도 명령에는 적용하지 않는다.
- F5의 공개용 처리는 셸을 실행하거나 변수/명령 치환을 평가하지 않는다. literal 인용 연결과 역슬래시를 풀고 원문의 해당 인자 전체를 가린다.
- 인증 문맥의 불확실한 ANSI-C/locale 인자는 공개 시 보수적으로 가린다. 인증 URL 전체와 --user 값도 가리므로 공개 정보가 줄 수 있다.
- 일반 설명·비인증 URL·비인증 헤더는 정상 대조군으로 보존한다. 동적 프로그램 출력의 모든 비밀을 탐지한다고 주장하지 않는다.
- 운영 DB의 기존 값과 제공자 원본은 수정하지 않는다. 새 보관과 기존 반환 경계를 각각 확인한다.
- 독립 재검토는 기존 w4가 맡는다. 여기서 한 확인은 작성자 자기 확인이다.
- 운영 데이터·실제 직원·모델·공용 실행기·메인·설정·대표 화면을 바꾸지 않는다. 새 직원/하위 에이전트를 만들지 않는다.
- 원 검토 자료는 보관 과정에서 경로가 옮겨졌다. 실제 원본은 after/residual.test.ts이며 사본에서는 artifacts 아래로 놓았다.
- 첫 시험 호출의 파일 필터가 숨김 경로를 찾지 못한 준비 실수는 결과에서 제외했다. ./로 명시해 두 실패를 다시 확인했다.
- 과거 관련 기억은 새 승인으로 쓰지 않았다. 과거 병렬 선호와 다른 업무의 적용 승인은 현재 순차·금지 범위보다 앞서지 않는다.
