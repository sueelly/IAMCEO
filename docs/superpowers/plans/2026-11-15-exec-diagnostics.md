# 실행 근거 진단 구현 계획

실행: 기존 직원 본인이 순차 구현. 승인 범위는 계약 r1의 격리 구현·시험·커밋·자료 제출이다. 별도 승인 질문·하위 에이전트 없이 진행한다.
설계: ../specs/2026-11-15-exec-diagnostics-design.md. TypeScript/Bun/기존 Store와 Orchestrator를 사용한다.

## 단계

- [x] 실제 exec_diagnose 도구 경로의 실패 시험을 작성하고 기준에서 실패를 확인한다. 입력은 task_id/report_id/check_index로 고정한다.
- [x] server/orchestrator.ts의 기존 contextLog 선택에 선택 관찰을 붙이고 같은 경로를 재사용한다. server/agent-tools.ts에 엄격한 읽기 전용 도구를 등록한다.
- [x] server/harness-evidence.ts의 보호된 읽기를 메타데이터와 함께 재사용한다. 1MiB 진단 제한과 192MiB 관문 제한을 구분한다. 새 server/harness-exec-diagnostics.ts에서 반환 가능한 고정 메타데이터만 만든다. server/harness-command.ts의 기존 파서로 명령/위치 관찰을 설명하되 기존 proof 결과는 바꾸지 않는다.
- [x] 서버 기록으로 권한·실패 검사·계약을 확정하고, 원시 본문·출력·경로·세션을 반환하지 않는다. 현재 재조회와 당시 미확인을 구분한다.
- [x] tests/harness-exec-query.test.ts에서 접근·가림·부분 기록·짝·선택·시각·위치·무변경을 영구 회귀로 남긴다. 필요한 관련 회귀와 코드 검사만 낮은 동시성으로 실행한다.
- [x] 최신 메인 재확인, 고정 커밋·불변 추가 차이·원응답·필드 표·정확한 사용법·적용/되돌리기·미검증을 HTML+md와 원기록으로 제출한다. 계약r1 criterion1~3과 실제 명령으로 보고한다.

## 검토 초점

직원·프로젝트 범위 이탈, 자유 경로 입력, 이미 가린 명령의 거짓 불일치, 출력 안 가짜 명령, 부분 기록의 거짓 부재, 미지원 이벤트의 성공 승격, 현재 관찰의 과거 소급을 막는다.

## 근거·판단 기록

- 메인 소스 ffaa632, server_check DB32/32와 label 확인. 부팅 바이너리 커밋은 이 조회로 독립 확인하지 못한다.
- exp-86a4318887dc6cc9d8cb2a566506cfc60586d5e3은 직원 AI 결과다. 위치 불일치도 명령 미발견으로 보인다는 비교 단서만 적용했다. 비서 누락 원인이나 새 수정 통과 근거로 쓰지 않는다. 과거 실제 검증 수를 이번 결과로 소급하지 않는다.
- 원 진단업무 tk_6NzefaUS0u6g는 막힘이다. 그 격리13/회귀127은 기존 형식 대조이며 실제 원인·수정 후 결과가 아니다. 원업무는 닫지 않는다. 환경 정책도 미정 그대로다.

- 자기 확인 결과: 신규41통과/0실패, 관련114통과/0실패, 최종 tsc --noEmit 종료0. 선택 합계155건이다. 이후 진단의 고정 custom 이벤트 종류 집계만 추가해 신규41과 코드 검사를 재검사했으며 완료 관문에 영향 없는 기존114는 이유 없이 반복하지 않았다.
- 동일 신규41단언을 불변 기준 사본에서 실행하면 8통과/33실패다. 기준에는 exec_diagnose가 없어서 난 실패이며 비서 누락 결함33건이나 권한 검증8건 통과를 뜻하지 않는다.
- 초기에 긴 인자 시험을 API 500자 상한 안으로 넣지 않아 준비 단계가 한 번 실패했다. 현재 API 동작을 바꾸지 않고, 과거 행 반환 경계를 가짜 SQL 행으로 주입해 검증했다. query-before.txt는 준비 중 결과이고 baseline-final-41.txt가 최종 동일 단언의 기준 결과다.
- 반복 완료를 별도 호출/결과 쌍으로 오인하거나 같은 식별자의 미지원 이벤트에 앞 파서 결과를 붙이지 않는 반례를 추가했다. 앞 경계 없는 잘린 조각은 진단에서 제외하되 완료 관문의 기존 읽기 의미는 바꾸지 않았다.
- 정상 조회·거절의 직접 도구 처리에서는 격리 DB 전체와 파일/가짜 실행기가 같다. MCP 공통 operation 경계에서는 기존 응답 보관 두 행만 생기며 그 밖의 계약/보고/근거/활동과 제공자 기록은 같다. 같은 operation 재요청은 원 관찰 시각의 응답이다.
- 반환에는 명령/위치 원문 자체가 없다. 기존 가림을 적용한 저장 명령으로 대조 가능 여부만 정하고 이미 가린 값은 unavailable로 남긴다. 출력/대화/환경/원시 세션·호출·파일 경로를 반환하지 않는다.
- 자체 검토: 설계·코드·직접/operation 경로·반례 원응답을 작성자가 대조했다. 기존 w4의 독립 검토 전이며 실제 비서 누락 원인은 미확인이다. 본사 원7항목과 환경파일 정책은 이번에 마감하지 않는다. 과거 실패27건은 미재검사다.
