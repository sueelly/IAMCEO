# F1: 자료 이동 원시험의 실패 경계 확인

작업 tk_818kp33hj5lG, 계약 r1. 기존 통합 브랜치/워크트리에서 순차 진행한다.
고정 후보5ac6a39와 메인기준c51을 보존한다. 운영 적용/공유 메인 전송은 범위 밖이다.

## 현재 사실과 미정
- 최초 시험은 이동 뒤41개 대기에서30초를 넘겼다. 격리 DB는 목표41/원래0이다.
- 당시 DOM/WS/요청 순서는 없다. await를 추가한 진단 정상군은 원인 해결 증거가 아니다.
- 파일 이동은 트랜잭션 뒤 file이벤트를 내고, 웹은 fileRevision/preview로 페이지를 갱신한다.
- 페이지 hook은 진행 응답을 취소/교체하고, 이미 읽은 범위를 reconcile한다.

## 가설과 가르는 관찰
1. 구독 준비/같은cursor 스냅샷과 이동이 겹쳐 file 이벤트가 읽히지 않는다: 서버발행과 WS수신/스냅샷/후속조회 순서를 비교한다.
2. 더보기/새로 읽기 동시 응답이 갱신을 취소하거나 낡은 상태로 덮는다: 요청/취소/응답 ID,페이지 내용과 DOM을 비교한다.
3. preview 밖 옛 자료가 전체40개를 읽은 목록에 들어올 때, refresh가40개만 남기고 후속을 스크롤까지 보류한다: total41/hasMore/cursor와 DOM40/스크롤/열린본문 표시를 비교한다.
4. 시험이 실제 준비 완료보다 먼저 움직인다: 원 조작 순서에서 수동적 관찰을 수집하고, 정확한 전제만 좁게 고정한다.

## 순서와 수용 기준
- 조작 전 리스너를 설치하고 메모리에 시각·HTTP/WS/이벤트·자료ID·DOM만 모은다. 조작 사이 관찰 await나 새 조회를 넣지 않는다.
- 자기 소유 소스 사본과 새 격리 데이터만 사용한다. 최초1회 수동적 관찰 후 특정 순서를 고정한 반례로 가설을 판정한다. 통과할 때까지 무작정 반복하지 않는다.
- 동일 시험바이트로5ac/c51을 비교한다. 원단언41/옛자료1/열린본문 업무표시0과 원30초/전체60초를 유지한다.
- 원인을 확인한 뒤 필요한 최소 제품/시험 수정과 수정 전후 동일 단언을 연결한다. 빠진 이벤트/조회 정상 검출 및 기존 정상조작을 확인한다.
- 바뀐 경계의 회귀/PC390/코드 검사만 선택한다. 제품 영향 밖의 통과 독립 근거는 재사용하며 새 실행으로 세지 않는다.
- 검증된 단위만 일반 커밋/작업브랜치 전송/원격 일치. 훅 우회 옵션, 한도 변경, 이벤트유실 허용, 새로고침/수면/기대 완화는 사용하지 않는다.
- 원실패의 정확한 과거 DOM은 미확인으로 남긴다. 제품 결함과 시험 전제, 새 직접 관찰과 과거 추론을 구분한 자료 한 개를 납품한다.
