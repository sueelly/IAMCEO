# 최신 메인과 대기열·승인 통합 검증 계획

작업: tk_818kp33hj5lG, 계약 r1. 기존 통합 워크트리와 작업 브랜치를 재사용한다.

## 고정 범위
- 독립 확인한 통합 입력: 55bec2bd5e2fca5446cb16ee3a44cc02eb97fdf6.
- 직접 가져온 원격 메인: c51a9c2369ff7ba576ce9dab2e16eeff1ae0f397.
- 연결 시험만: bc3ab56c709621c5b70e43f3caff325484da49e6 (4fb..bc3 한 파일 +11/-3).
- 공유 기본 체크아웃 43b1508과 다른 직원·이전 검토·운영 자료를 보존한다.
- 공유 메인 전송과 실제 서비스 적용은 이번 납품 범위가 아니다.

## 판정 가능한 순서
1. 새 HTTP 교차 시험을 먼저 작성한다. 현재55에서는 history=50 미지원으로 실패해야 한다.
2. 원격 메인을 일반 합치기로 연결한다. HTTP와 공유 타입의 양쪽 의미를 확인한다.
3. 같은 소스에서 history/cache/cursor/인증, 브라우저 인증 세대와 자료 갱신을 선택 확인한다.
4. 승인 대기 중 읽기와 원ID/수신null/권한/민감정보 제외를 함께 확인한다. 같은 승인 영수증과 입력1회·다른 내용409·unknown·실제 footer 순서를 유지한다.
5. 최신 메인과 최종판에 동일한 bc3 시험 바이트를 사용한다. 원 클릭, 잠김/끊김, 초안, 8/20/40초 단언을 유지한다. 표적과 연결5건을 비교하며 기존 실패를 제품 통과로 바꾸지 않는다.
6. PC1280/390 승인→ended+뒤 작업 원응답, 초기 같은 cursor 및 자료 갱신 브라우저 검사를 고른다. 운영주소/토큰/HC/HERDR 상속 없는 대역만 사용한다.
7. 최종 코드 검사와 제품 바이트 보존을 확인하고 검증 단위 커밋 후 작업 브랜치에 일반 전송한다. 직전 원격 메인 추가 변경은 같은 브랜치에서 보존하고 바뀐 위험만 재검증한다.
8. 한 결과 자료에 실제 명령/종료/원응답/입력횟수·새 기준 비교·미확인·독립 확인 범위를 연결한다.
