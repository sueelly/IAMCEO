구조: 실제 CoreRunner와 Orchestrator를 사용한다. 외부 터미널 RPC만 격리 대역으로 바꾼다.

겹치는 범위: 작업 실행 체계의 terminal-approval-inbox 브랜치도 core.ts와 orchestrator.ts를 다룬다. 그 워크트리는 읽기만 한다. 합칠 때 기존 변경과 각각의 회귀를 유지해야 한다.
보존: 기존 대화·초안·자료·대기열·unknown 입력·보류21개·실행 중 시험을 변경하지 않는다. 임시 폴더도 삭제하지 않는다.


검증 범위: 변경 동작과 정상군 7건, 관련 코어 회귀 238건, PC·좁은 화면 2건, 실제 herdr-core 0.1.18+가짜 CLI 왕복 8개 확인, 코드 검사와 컴파일을 통과했다. 실제 모델 호출은 없었다.
기준판 대조: 현대 footer 미관측과 불필요한 보고 보완을 새 검사로 재현했다. legacy Herdr의 24개 실패는 기준판과 후보판이 같다.
시험의 기존 경합: lifecycle-recovery의 응답 유실 시험은 기준판에서도 보고 보완이 자동 출발하면 실패했다. 원 실행 종료·원 입력 1회·보완 1개를 직접 확인하도록 바꿨다. 제품의 보고 보완 규칙은 바꾸지 않았다.
아직 미확인: 직원별 현재 제한·보류 상세·정확한 서버 수신 시각, 전체 대기 원인, 독립 확인, 같은 운영 서비스 적용과 적용 후 자동 진행. 이를 구현 검증과 섞지 않는다.
대표용 결과 자료는 Git 밖 evidence의 한 HTML로 만든다. 실행 파일·운영 관찰·캡처·원응답·실행 기록도 소스 커밋에 넣지 않는다.
