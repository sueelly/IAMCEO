# 직원별 업무 흐름과 실행 일치 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 독립된 전달 회귀와 화면 구현은 superpowers:dispatching-parallel-agents 절차로 파일 소유권을 나누어 진행한다.

**Goal:** 사용자가 지시한 업무의 순서·파생 관계·담당 직원·현재 위치·다음 조치를 같은 실행 근거로 확인하고, 완료 전에 다음 업무로 넘어가는 오류를 막는다.

**Architecture:** 기존 업무 단계 기록을 보완하고 서버에서 직원별 업무 흐름을 계산한다. 웹의 팀·대화 화면은 같은 동기화 스냅샷을 사용한다. 전달 큐는 보호된 입력과 선행 업무를 구분한다.

**Tech Stack:** Bun, SQLite, TypeScript, React, HTML/SVG, 기존 v2 WebSocket 동기화.

**Spec:** 이 문서의 요구사항과 완료 조건. 사용자 2026-11-17 확정: 직원마다 한 행을 차지하며 왼쪽 업무가 끝나야 오른쪽 업무가 시작된다. 파생 업무는 관계 있는 노드에 선으로 연결하고 클릭하면 상세를 연다.

## 구현 중 확인한 경계와 결정

- 순서 관리 도입 전의 모든 전달 기록을 선행 업무로 삼으면 과거 기록 때문에 새 입력이 멈춘다. v37은 현재 미처리 입력과 현재 실행만 순서에 등록하고, 이후 명시적으로 들어온 업무를 지속 등록한다. 과거 전달은 완료로 꾸미지 않고 ‘이전 업무’로 남긴다.
- 부모 업무를 끝내기 위한 파생 보완은 같은 업무에 이어 붙이며, 그 사이에 들어온 독립 업무보다 앞에 배치한다. 같은 직원의 형제 파생 업무는 순서를 지킨다. 총괄은 팀 전체의 보고·승인·조정을 계속 받을 수 있다.
- 보호·복구 완료된 과거 입력과 실제 선행 업무를 구분한다. 수신 불확실한 실제 쓰기, 중단·중복 방지, 자동 재전송 한도는 유지한다.
- 승인 해제의 갱신 시각을 보존하고, 단계 우선순위와 별개로 열린 결재·할 일·미처리 입력·미실행 검사·현재 파생 업무의 실패를 완료 검사에서 각각 확인한다.
- 실행 강조는 현재 업무가 연결된 실행 저널과 최근 검증된 관측을 함께 요구한다. 연결이 끊기거나 관측이 90초를 넘으면 강조를 해제한다. 이미 실행 중인 다른 업무가 있으면 그 실제 위치를 우선한다.
- 프로젝트 전체 조회는 계약·완료 근거를 일괄 조회한다. 완료 이력 20→60건의 SQL 읽기는 계약 없음 25→25, 공유 계약과 개별 계약 26→26이었다. 단일 업무 갱신에는 무관한 과거 보고를 읽지 않는다.
