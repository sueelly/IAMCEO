# IAMCEO 활동 자동 보관과 기억 활용 피드백

> **For agentic workers:** Execute the owned task with regression tests before implementation; preserve production runs and settings.

**목표:** IAMCEO의 모든 프로젝트 활동을 hj-brain에 출처와 함께 보관하고, 직원이 업무에서 참고한 기억의 활용 결과를 남긴다.

**구조:** 기존 SQLite 원본과 개발 기억 API를 사용한다. 자동 보관과 피드백을 영속 대기열에 넣고 네트워크 실패 후 이어 보낸다. 판단의 정본과 실행 권한은 IAMCEO에 유지한다.

**기술:** Bun·TypeScript·SQLite. 기존 hj-brain REST 계약을 유지한다. 새 의존성은 추가하지 않는다.

**확정 범위:** 사용자는 자동 보관·피드백·일시적인 웹서버 재시작을 승인했다. 현재 작업의 대상은 IAMCEO의 다섯 프로젝트와 앞으로 생성되는 프로젝트이다. 이 ChatGPT/Codex 대화와 다른 앱 전체의 추가 수집은 별도 범위 답을 받지 않았으므로 이 구현의 완료 주장에 포함하지 않는다.

| 요구 | 완료 조건 |
| --- | --- |
| R1. IAMCEO의 지시·대화·업무·단계·결재·자료를 원문 출처와 함께 자동 보관한다. | A1. 이전 원본과 새 변경을 보관하며, 재시작과 중복 이벤트에도 같은 내용을 중복 전송하지 않는다. 긴 원문은 분할하고 각 부분의 순서와 전체 수를 보존한다. |
| R2. 대표 원문과 AI 보고·해석을 구분한다. | A2. 화자·시각·프로젝트·업무·원본 ID를 기록하고 AI 보고를 대표 결정으로 바꾸지 않는다. 키·인증값은 정제한다. 첨부는 원본 연결과 메타데이터를 기록하며 바이너리 전문 보관으로 표현하지 않는다. |
| R3. 받은 기억의 활용 결과를 직원이 직접 남긴다. | A3. 현재 업무에 받은 타 업무 기억의 미평가 항목을 보고 전에 안내한다. 직원이 명시한 평가만 보관하며 성공 여부에서 긍정 평가를 추정하지 않는다. 같은 업무의 자기 기록과 과거 미평가 기록은 강제 평가하지 않는다. |
| R4. 연결 장애와 재시작에도 보관·피드백을 잃지 않는다. | A4. 네트워크 실패는 영속 큐에 남고 다시 전송한다. 원격 영수증과 실패를 구분한다. 프로젝트가 끈 연결은 전송하지 않는다. |
| R5. 기존 연결과 누락분을 복구한다. | A5. 로컬·Tailscale 상태, 실제 업로드와 다음 검색을 확인한다. 기존 rejected 11건은 원격 중복 여부를 대조한 뒤 다시 처리하고 원래 시도 이력을 보존한다. |
| R6. 현재 실행·설정·대화를 보존한다. | A6. 상한을 변경하지 않는다. 검증된 main 릴리스를 웹만 재시작해 반영하고 직원 실행과 대화 ID를 확인한다. |

## 구현 단위

- [x] `server/integrations/memory-archive.ts`와 회귀 검사: 원본 수집·분할·중복 방지·민감값 정제·재시작 후 이어 보관을 구현한다. 독립 `MemoryArchive`는 기존 `Store`와 `DevMemory`를 받는다.
- [x] `server/integrations/memory-feedback.ts`와 회귀 검사: `MemoryFeedback`의 검색 등록·명시 평가·미평가 조회·영속 전송을 구현한다. 공개 계약은 구현 담당자가 루트에 전달하고 루트가 보고와 검색 경계에 연결한다.
- [x] `server/integrations/dev-memory.ts`와 설정 회귀 검사: 런타임 홈의 연결 설정 파일을 환경 변수 누락 시 읽고, 완전한 환경 변수 쌍을 우선한다. 비밀값은 파일 경로로만 보관한다.
- [x] `server/db.ts`, `server/orchestrator.ts`, `server/agent-tools.ts`: 추가 마이그레이션과 라이프사이클·검색·보고·도구 규칙을 통합한다. 기존 v41은 수정하지 않는다.
- [ ] 관련 검사·타입·빌드·독립 검토 후 커밋과 작업 브랜치/main 일반 푸시를 수행한다.
- [ ] 실제 보관·기억 검색·피드백 전달과 기존 데이터·상한·실행 보존을 확인한다.

## 검토 초점

네트워크 응답 유실과 같은 이벤트의 재수신, 긴 한국어 원문과 비밀값 경계, 사용하지 않은 기억의 허위 긍정 평가, 프로젝트·업무 범위 혼합, 서비스 재시작 중 직원 실행 보존을 검사한다. 개인 판례 분석의 기존 자료 범위·예산·진행 상태는 변경하지 않는다.

## 개발 검증

기억·연결 설정·마이그레이션 검사 113건과 하네스·후속 실행·상한·런타임 검사 205건을 통과했고 타입 검사도 통과했다. 독립 검토에서 발견한 짧은 접속 코드 정제, 여러 업무의 전달 귀속, 병합 업무의 평가 누락, 종료 뒤 늦은 응답, 인증 복구 후 재시도를 각각 회귀 검사로 확인했다.

전체 시험은 통과로 판정하지 않았다. 저장 최적화 2건과 공통 도구 15건은 변경 전 `49df056`에서도 같은 검사들이 실패했다. 전체 브라우저 시험은 격리 폴더·환경 변수 경계에서 실패했으며 이어지는 장기 실패 실행은 이 작업 소유 프로세스만 종료했다. 관련 로그와 비교 결과는 Git 밖의 private 작업 경로에 보존한다.

최신 원격 main `65cd908`의 보고·자료 작성 개선과 통합한 25개 검사 묶음 346건이 통과했다. 웹 종료 중 기억 검색이 늦게 끝나도 입력 전달과 DB 접근이 이어지지 않는 회귀 검사를 포함한다.
