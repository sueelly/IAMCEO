# 비동기 최종 검수 전담 직원

프로젝트의 일반 직원이 수행을 마치면 별도 검수 직원이 최신 완료 근거를 검토한다. 총괄은 통합과 수정 업무의 배정, 승인과 운영 예외를 맡는다.

| 요구 | 완료 조건 |
| --- | --- |
| R1. 실행하는 프로젝트에 전담 직원이 한 명씩 있다. | A1. 서버를 재시작하거나 프로젝트 실행을 켜도 인원이 중복되지 않는다. 검수 요청이 있을 때만 세션을 사용한다. 보관 프로젝트와 본사는 등록 대상에서 제외한다. |
| R2. 검수는 제작 직원과 독립하고 일반 후속 업무를 지연시키지 않는다. | A2. 이전 총괄 검수 입력을 전담 쪽으로 이어 붙이고, 통과·수정 결과는 최신 보고 ID로 판정한다. 전담 직원은 읽기 도구와 검수 결과 도구만 사용한다. |
| R3. 통합과 예외 조정은 기존 순서를 따른다. | A3. 같은 브랜치와 커밋의 통과 확인 뒤에만 통합 예정 업무를 만든다. 수정 요청은 해당 문제의 별도 일감 한 건과 총괄 알림을 만든다. 기존 승인과 중단, 수신 불확실은 보존한다. |

## 검증

- 기존 수행 완료, 비동기 검수, 최신 보고 교체, 원격 통합과 브랜치 정리의 회귀를 실행한다.
- 프로젝트별 단일 전담 배치, 총괄 대기열에서의 이동, 역할 권한, 중복 검수와 수정 방지, 대상 보고의 현재성을 검사한다.
- 운영 DB 복제본의 이주와 서명 실행 파일의 격리 기동을 확인하고, 원격 main과 로컬·Tailscale 릴리스 SHA를 대조한다.
