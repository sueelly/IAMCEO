# 최종 검수 뒤 main 통합과 수정 업무

직원이 맡은 조건을 통과하고 총괄이 같은 커밋을 확인하면 통합 담당자가 main에 반영할 수 있다. 실패는 발견한 범위의 별도 업무로 추적한다.

| 요구 | 완료 조건 |
| --- | --- |
| R1. 총괄의 확인은 통과한 최신 보고와 검수한 커밋을 가리킨다. | A1. 확인 대기, 이전 계약, 다른 커밋은 통합 업무 생성과 실행 전달을 막는다. 최신 검수가 확인되면 연결된 예정 업무를 한 건 만든다. |
| R2. 통합 담당자는 main 반영을 확인한 다음 해당 작업 브랜치를 정리한다. | A2. 지시에는 검수한 커밋과 브랜치, main 일반 푸시, 원격 main 검증, 브랜치 끝점 및 다른 사용 여부 조건이 남는다. |
| R3. 검수나 통합에서 확인한 문제는 별도 수정 업무로 올린다. | A3. 확인한 보고와 원 업무를 연결한 예정 항목이 생긴다. 같은 보고를 다시 처리해도 한 건이다. 통합 전에 문제가 발견되면 기존 검수를 철회한다. |

## 구현과 검증

- 회귀 검사에서 검수 대기, 다른 커밋, 검수 뒤 전달, 철회, 수정 업무 중복 방지를 먼저 확인한다.
- 총괄 도구와 대기열이 원 업무의 검수 판을 대조한다. Git 실행은 지정 담당자의 배정과 각 저장소의 권한을 따른다.
- 이미 통합된 기록과 기존 승인·보류를 보존한다. 작업 브랜치 정리는 새 통합 업무에서 적용한다.
