# 독립 업무 착수와 자체 검증 후 통합

담당자가 맡은 변경을 검증하고 프로젝트에서 허용한 범위에서 main에 통합한다. 독립 검수는 완료 조건과 실제 산출물을 따로 확인하고 발견한 결함의 수정 업무를 연결한다.

| 요구 | 완료 조건 |
| --- | --- |
| 독립적인 업무는 직원의 과거 배정 순서 때문에 멈추지 않는다. | 새 업무 사례와 기존 대기열 사례에서 독립 지시가 전달되고, 명시한 선행·중단·승인·불확실한 수신은 보존된다. |
| 직원은 독립된 부분을 하위 에이전트와 병렬로 처리할 수 있다. | 기존·신규 직원 설정과 실제 실행 인자를 대조한다. 지속적인 업무 소유·인계·독립 검수에 필요한 별도 직원 배정은 유지한다. |
| 코드 작성자는 자체 검증이 끝난 판을 통합할 수 있다. | 격리 저장소에서 검수자 판정 전 승인된 SHA가 main에 도달하고, 브랜치 전용 계약은 범위를 벗어나지 않는다. |
| 전담 검수자는 비동기로 판정하고 필요한 보완을 남긴다. | 실제 검수 도구 호출, 동일 보고의 중복 전달 제한, 불확실한 묶음과 독립적인 새 검수, 새 결함의 단일 수정 업무를 확인한다. |

운영에서 기존 검수 세션의 불확실한 수신이 다른 검수의 실제 입력까지 차단하는 경우를 검사한다. 원래 묶음의 시도와 결재 상태를 보존하고, 아직 전송하지 않은 무관한 업무를 별도 검수 세션이 수신하고 판정하면 통과한다.

운영 반영은 검사한 Git 커밋의 빌드와 서비스 응답을 확인한다. 검증과 운영 자료는 분리하고 기존 세션·보류·결재·수신 기록을 보존한다.
