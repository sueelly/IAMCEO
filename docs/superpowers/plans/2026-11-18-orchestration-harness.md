# 총괄 오케스트레이션 하네스 구현 계획

사용자의 2026-11-18 요구와 후속 실행 승인을 기준으로 구현한다. 총괄은 업무 정의·배정·모니터링·예외 해결·비동기 최종 확인·즉답을 맡는다. 직원은 완료 조건이 충족될 때까지 수행한다. 하네스 통과 즉시 후속 업무가 시작되고 총괄 확인은 비동기로 진행한다.

## 범위와 판정 기준

- R1. 총괄의 실행 권한은 조정과 조회에 한정한다. A1. 도구와 CLI 경로에서 제작·수정 요청을 차단하고 허용된 조정 요청은 통과시킨다.
- R2. 업무 계약에는 입력·산출물·범위·제한조건·완료 조건·제외 범위를 기록한다. A2. 저장·전달·재개·검사에서 같은 계약 판을 사용하고 불완전한 계약은 실행 전에 보완한다.
- R3. 직원은 남은 조건을 자동으로 이어 수행한다. A3. 총괄이 바빠도 계약이 있는 수행 가능한 직원의 다음 실행이 생성된다.
- R4. 세 번 반복 실패·막힘·이상은 총괄이 먼저 해결한다. A4. 자동으로 대표 결재를 만드는 대신 원인과 변경된 접근을 총괄에게 연결한다. 기존 열린 대표 결재는 보존한다.
- R5. 검사 통과 뒤 후속 업무를 즉시 시작한다. A5. 총괄 처리 상태와 독립적으로 대기열이 진행된다.
- R6. 총괄은 완료를 비동기 확인한다. A6. 현재 계약·산출물·근거를 조회하고 정정에 따른 보완을 연결할 수 있다.
- R7. 상태와 대기열은 실행 사실로 갱신한다. A7. 재시작·중복 이벤트에서 중복 실행·완료 역전이 없고 실패 이유가 남는다.
- R8. 총괄은 사용하지 않는 직원을 해제하고 필요한 직원을 배정한다. A8. 해제는 기록을 보존하는 휴면으로 정하며 실행·대기·승인·백그라운드 작업이 없는 직원만 대상으로 삼는다.
- R9. 총괄은 배정 후 턴을 끝내고 질문에 직접 답한다. A9. 보고 일괄 입력에 처리 한도를 적용하고 사용자 입력과 개입을 우선한다.
- R10. 기존 승인·중단·한도·수신 불확실 상태를 준수한다. A10. 모든 자동 경로에서 같은 실행 입장 검사를 통과하고 실제 수신 여부를 확인한다.

## 설계

기존 task_contracts, task_continuations, task stage, 보고·실행 증거와 ordinaryInputAdmitted를 확장한다. 새 실행 엔진을 추가하지 않는다. 완료 검사에 통과한 직원 보고를 수행 완료의 근거로 사용하고 총괄의 사후 검토 상태를 별도로 추적한다. 각 업무의 승인된 통합·적용 조건만 완료 계약에 포함한다.

사용자가 확정한 수치는 실패 반복 세 번이다. 후속 점검 간격은 기존 30초를 재사용하며 총괄 보고 묶음은 작은 제한을 설정하고 설정된 제한을 검증한다. 미사용 직원은 휴면으로 처리한다. 기존 계약은 명시적 새 필드를 보완할 수 있게 호환성을 유지하며 원래 범위를 만들어내지 않는다.

## 구현 단위

### 1. 명시적 업무 계약

server/harness.ts, server/store.ts의 계약 직렬화, server/agent-tools.ts의 계약 입력, DB migration, workflow 전달과 관련 검사를 수정한다. 입력·산출물·제약·제외를 저장하고 전달한다. 기존 계약의 원문과 버전을 보존한다. 먼저 누락된 전달·직렬화 회귀 검사를 실패시킨 뒤 구현한다.

### 2. 총괄 권한과 짧은 조정 턴

server/roles, server/runner, agent tool 권한 및 관련 검사를 수정한다. 조정·조회 도구를 허용하고 직접 제작 경로를 차단한다. 일반 보고 묶음은 제한하고 질문·개입을 우선한다. 지원하는 제공자별 실제 실행 구성과 API 호출 경계를 시험한다.

### 3. 직원 자동 후속 실행과 예외 개입

server/task-continuation.ts, server/task-progress.ts, server/store.ts의 실패 escalation, 관련 runtime 검사를 수정한다. 수행 가능한 미완료 작업은 원 담당 직원에게 이어 보낸다. 계약 보완·새 담당·실패 반복·막힘은 총괄에게 보낸다. 재시도에 의한 중복·대표 중단·수신 불확실·기존 결재 회귀 검사를 먼저 만든다.

### 4. 수행 완료와 비동기 확인 연결

server/orchestrator.ts, workflow와 stage projection, 관련 완료·대기열 검사를 수정한다. 직원의 현재 계약 검사 통과를 후속 실행 해제 근거로 삼고 총괄 확인 상태를 남긴다. 미사용 직원의 휴면과 상태 갱신을 연결한다. 총괄이 working인 상태에서 후속 업무가 진행되는 검사를 포함한다.

## 검증과 제공

각 단위는 실패 회귀 검사 → 구현 → 해당 검사 통과 순서로 수행한다. 통합 후 bun run typecheck, bun test tests, bun run build를 실행한다. 기존 실패는 같은 기준판에서 재현하여 구분한다. 독립 코드 검토 뒤 발견한 결함을 수정하고 검증된 내용만 커밋한다. 작업 브랜치를 origin에 일반 푸시하고 원격 HEAD 일치를 확인한다. IAMCEO의 main 통합·운영 배포는 이 저장소에 부여된 권한을 별도로 확인한다.

## 검토 초점

- 옛 계약과 기존 완료 데이터의 의미를 보존한다.
- 중복 보고·정정 보고·재시작이 실제 시도 수를 늘리지 않는다.
- 총괄 검토 대기가 직원의 다음 작업을 막지 않는다.
- 일반 API와 CLI 도구로 역할 제한을 우회할 수 없다.
- 중단·승인·입력 불확실·외부 대기 업무를 자동 실행하지 않는다.
