# 완료 기준과 프로젝트별 실행 상한 구현 계획

> **For agentic workers:** Use superpowers:executing-plans or superpowers:subagent-driven-development to implement each task with regression checks before implementation.

**목표:** 모든 실행 업무에 판정 가능한 완료 기준을 적용하고, 총괄은 기준 충족까지 재배정하며 같은 실패가 세 번 이어지면 결재함으로 넘긴다.

**구조:** 기존 업무 계약·반복 감시·영속 후속 큐를 확장한다. 실행 자리 확보 직전에는 전체 상한과 프로젝트 상한을 함께 검사한다. 역할 규칙은 사용자 정의 템플릿과 이미 열린 세션에도 이어진다.

**기술:** Bun, TypeScript, SQLite, React. 별도 의존성은 추가하지 않는다.

**명세:** 2026-11-18 사용자 요청과 아래 확정 요구를 구현한다. 같은 작업 워크트리 `show-workflow-20261117`, 브랜치 `feat-show-workflow-01a1e4ba`를 사용한다.

## 요구와 완료 조건

| 요구 | 판정 가능한 완료 조건 |
| --- | --- |
| R1. 실행 업무에는 총괄 또는 대표가 확정한 완료 기준을 둔다. | A1. 과거 업무·새 업무·직원의 미확정 기준 모두 확정 기준 없이 완료 보고나 최종 완료로 통과하지 않는다. 기준이 빠진 실행 업무는 총괄의 기준 작성 대상으로 이어진다. |
| R2. 총괄은 남은 기준을 충족할 때까지 직원에게 수정과 검토를 재배정한다. | A2. 기준 작성·배정·실패·보완·통과·적용·완료의 후속 큐가 이어지고 완료·대표 중단·열린 승인 뒤에는 임의 실행을 만들지 않는다. |
| R3. 같은 실패가 세 번 연속 발생하면 결재함에 올린다. | A3. 세 번째 실제 실패에서 한 장만 생기며 두 번째까지는 조정이 계속된다. 재시작·같은 보고 재처리로 중복 카드나 시도를 만들지 않는다. 결재 전 총괄의 reopen·재배정으로 우회할 수 없다. |
| R4. 총괄은 업무 조정만 맡는다. | A4. 기본·사용자 정의 역할에 기준 정의, 배정, 검토 요청, 상태 종합을 적용한다. 제작·구현·제품 설계·배포는 담당 직원에게 맡기고 기존 역할의 상충 지시를 제거한다. |
| R5. 전체 및 프로젝트별 동시 실행 상한을 설정할 수 있다. | A5. 설정 저장·새로고침 후 값이 유지되며, 한 프로젝트가 상한에 도달해도 다른 프로젝트는 전체 여유 내에서 실행된다. 전체 상한은 모든 프로젝트의 합계에 적용된다. |
| R6. 상한을 낮춰도 실행 중인 업무를 중단하지 않는다. | A6. 현재 실행을 보존하고 새 자리 확보만 기다리며, 상한을 높이면 대기 입력을 다시 확인한다. 동시 펌프·재시작·수동 승인 흐름에서도 상한을 넘지 않는다. |

기존 전체 상한은 유지한다. 프로젝트 상한의 초기값은 전체 상한 따르기(null)이며, 별도 정수 1~64를 지정한다. 이는 실행 중단을 만들지 않는 구현 기본값이다. 후보·완료 과거 기록을 새 실행 승인으로 바꾸지 않는다. 원 지시·결재·중단·수신 불확실·계정 한도를 보존한다.
