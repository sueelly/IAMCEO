# 승인된 업무를 완료 조건까지 이어가기

한 실행의 보고가 끝나도 업무의 완료 조건이 남으면 후속 담당을 다시 정하고 실행을 이어간다. 2026-11-18 사용자 요청에 따른 기존 업무 흐름의 수정이며, 작업 위치는 `feat-show-workflow-01a1e4ba`의 별도 워크트리다.

## 확인한 원인

- 인용된 업무 `tk_eYc5ZKUxm2zP`는 수정 지시를 받은 뒤 막힘·검토 실패가 남아 있지만 v37 순서표에는 없다. 화면이 이 여부를 실제 단계보다 우선하여 이전 업무로 숨겼다.
- 실행 보고 의무는 막힘·질문으로도 마감되지만 업무 완료 의무를 계속 관리하는 생산자가 없다. 기존 펌프는 전달할 입력만 소비한다.
- 미배정에는 진행판 완료 카드, 직원이 직접 수행·보고한 일, 서버 세션 안내가 섞였다. 이는 실제로 실행할 미배정 업무 수가 아니다.
- 입력 보호는 서버 이전 뒤 수신 여부 확인, 사용자 중단, 불확실 전달 등 서로 다른 원인을 한 이름으로 표시했다.

## 구현 판단

후속 입력을 브라우저 타이머로 만들면 화면을 닫았을 때 멈추고 중복 기기가 경쟁한다. 각 직원에게 무조건 같은 지시를 다시 보내면 수신 여부와 검토 역할이 뒤섞인다. 서버가 영속적인 업무별 후속 상태를 가지고 프로젝트 총괄에게 다음 조정을 요청하는 방식을 채택한다. 총괄은 원 지시·계약·실패 근거를 받아 기존 직원에게 수정 또는 검토를 맡긴다.

v38은 후속 상태·생성 입력 연결·사용자 중단 토큰을 저장한다. 후보 등록만으로 실행 권한을 만들지 않는다. 이전 지시가 존재하고 명시적 미완료 근거가 있는 업무 또는 현재 순서표 업무를 추적한다. 진행판 완료 기록과 순수 안내는 제외한다. 새 지시는 동일 업무를 계속 추적한다.

후속 상태의 진척은 전달 시간이나 직원 heartbeat가 아닌 검사 결과·업무 단계·계약·원 지시의 변화로 판단한다. 생성 입력은 기존 일반 보고 보완과 분리한다. 같은 조건에서 후속 실행이 반복되어도 진척이 없으면 기존 반복 상한을 사용하여 원인과 남은 조건을 결재함에 남긴다. 완료로 숨기거나 자동 승인하지 않는다.

## 실행 순서

1. 실제 사례의 화면·후속 누락·중복·중단 경계 검사를 추가하고 실패를 확인한다.
2. 상태 투영과 실제 배정 근거를 수정한다. 후속 상태 저장과 조정기를 구현한다.
3. 기존 펌프·재시작·주기 확인·중단 경로에 조정기를 연결한다. 최종 완료의 적용 근거 검사를 추가한다.
4. 관련 회귀·브라우저·타입·빌드 검사와 전체 테스트 명령을 실행한다. 기존 환경 실패도 구분해 기록한다.
5. 검증된 변경을 커밋하고 작업 브랜치와 main에 일반 푸시한다. 정확한 main 릴리스를 배포하고 실제 사례·데이터 보존·Tailscale을 확인한다.

운영 기록과 접속 키는 소스에 넣지 않는다. 이번 수정에서 모델·토큰·동시 실행 한도를 늘리지 않는다. 구체적인 원 업무의 검토나 배포 사실은 후속 직원이 최신 근거를 확인해 남기며, 이 코드 수정만으로 자동 완료 처리하지 않는다.

## 검증 결과

2026-11-18 최종 소스에서 관련 회귀 검사 730개(42개 파일, 4,706개 판정)와 PC·모바일 브라우저 검사 12개가 통과했다. 타입 검사와 운영 빌드도 통과했다. 독립 검토에서 중단·보고 보완·재시작·최신 사용자 지시 범위를 재검사했으며 남은 P1/P2 차단 지적은 없었다.

운영 DB의 별도 복사본에서 v38 이전과 상태 투영을 확인했다. 사용자가 인용한 미완료 업무는 작성자·총괄·검토자 세 행 모두 ‘고칠 것’으로 표시되며 과거 업무로 숨지 않는다. 같은 업무의 후속 입력이 중복 생성되지 않는 것도 확인했다. 이 검사는 운영 입력이나 승인을 바꾸지 않았다.

전체 테스트 명령은 통과하지 않았다. 기존 전 과정 브라우저 시험은 격리 실행기 바깥의 작업 경로·등록되지 않은 서버 주소·환경 변수 구성 때문에 총괄 생성부터 실패했다. WebKit 실행 환경과 구형 가짜 소켓의 수신 영수증 계약 실패도 남았다. 이 설정을 우회하거나 검사 기대값을 약화하지 않았으며, 이번 변경의 실행·중단·전달·마이그레이션·실시간 화면 검사는 별도로 모두 통과시켰다. 전체 로그와 격리 재현 자료는 Git 밖의 작업 전용 비공개 경로에 보존한다.

배포는 커밋·원격 main 일치를 확인한 뒤 정확한 Git 릴리스로 수행한다. 배포 영수증에는 소스 SHA·실행 파일 지문·스키마·로컬과 Tailscale 확인·기존 데이터 및 대화 보존 결과를 남긴다. 이 문서의 구현 검사는 아직 진행 중인 개별 업무의 완료나 반영 영수증을 대신하지 않는다.
