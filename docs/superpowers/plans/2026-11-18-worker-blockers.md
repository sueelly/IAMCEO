# 직원 실행 정체 수정 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 실제 검사 성공을 작업 위치와 대조하고, 직원의 납품·보류와 업무 전체의 완료를 구분하여 승인된 다음 업무와 후속 조정이 진행되게 한다.

**Architecture:** 기존 증거 수집·업무 순서·후속 조정에 제한된 수정을 적용한다. 작업에 등록된 워크트리의 실행 위치를 인정하고, 순서를 차지하는 배정만 실행과 화면 양쪽에서 동일하게 계산한다. 전달되지 않는 안전한 입력은 총괄의 조정 대상으로 연결한다.

**Tech Stack:** TypeScript, Bun, SQLite, 기존 가짜 실행기와 격리 시험 환경.

**Spec:** 이 문서의 요구사항. 2026-11-18 기록 조사 결과에 대한 사용자의 수정 및 운영 반영 지시를 수행한다.

## 요구사항과 제약

- R1. Codex의 로컬 file URL과 절대 경로를 동일한 위치로 대조한다. 등록 직원 위치 또는 해당 업무 워크트리 내부의 실행만 인정한다. 다른 업무, 계약 이전, 실패·불확실 종료, 가려진 종료 코드는 통과시키지 않는다.
- R2. 보류·대표 중단은 해당 업무와 하위 업무에 적용한다. 직원의 유효한 납품 이후 독립 검토·통합 대기는 다른 업무의 실행을 막지 않는다. 새 보완 지시, 실패, 실행 중인 업무는 계속 순서를 차지한다. 업무를 자동 완료 처리하지 않는다.
- R3. 안전하게 대기 중이나 다른 업무 순서에 막힌 지시는 처리 중으로 오인하지 않는다. 총괄에게 기존 지시와 선행 업무를 연결하여 조정 요청을 한 번 생성한다. 원문 재전송·승인 응답·불확실 수신 복구를 대신하지 않는다.
- R4. 최신 원격 main과 함께 검증하고 작업 브랜치·main을 일반 푸시한다. 정확한 소스로 빌드한 릴리스를 운영에 반영하고 로컬·Tailscale 및 기존 ID·설정·세션 보존을 확인한다.
- 소스와 운영 자료를 분리한다. 진행 중인 다른 워크트리와 직원 프로세스는 보존한다.

## Review Focus

- 잘못된 file URL, 경로 접두사가 같은 다른 워크트리, 경로 이탈은 실행 증거가 될 수 없다.
- 납품 이후의 실패·재배정은 오래된 성공으로 해제되지 않는다.
- 보류된 부모의 자식은 실행하지 않으며 관계없는 승인된 업무만 진행한다.
- 수신 불확실·중단·사용자 결재는 새 조정으로 우회되지 않는다.
- 화면의 선행 대기와 실제 전달 판정이 일치해야 한다.

### Task 1: 실행 위치 대조

**Files:** `server/harness-evidence.ts`, `server/harness-exec-diagnostics.ts`, `server/orchestrator.ts`, `server/harness-worktree.ts`, `tests/harness-worktree-scope.test.ts`.
**Interfaces:** `matchExecChecks`와 읽기 진단에 선택적인 `taskWorktree`를 전달한다. 파일 URL 파서와 업무 경로 선택 함수를 공유한다.

- [ ] 정상 워크트리·하위 폴더 성공, 잘못된 URL·다른 경로·최신 실패를 재현한다.
- [ ] 검사 실패를 확인하고 로컬 URL 정규화와 업무 범위 대조를 구현한다.
- [ ] 실행 검사와 진단·완료 API 회귀 검사를 통과시킨 뒤 커밋한다.

### Task 2: 직원 배정의 순서 해제

**Files:** `server/store.ts`, `server/workflow.ts`, `tests/workflow-worker-order.test.ts`, `tests/workflow-assignment-release.test.ts`.
**Interfaces:** `WorkflowAssignment.blocksSequence`를 실행 판정과 화면에 함께 사용한다. 보류된 범위와 유효 납품을 구분한다.

- [ ] 보류된 부모/자식, 다른 업무 실행, 납품 후 검토 대기, 새 수정 지시와 실패의 회귀 검사를 먼저 작성하고 실패를 확인한다.
- [ ] 완료 상태를 바꾸지 않고 배정의 선행 차단만 계산한다.
- [ ] 작업 순서·복구·화면 회귀 검사 및 타입 검사를 통과시킨 뒤 커밋한다.

### Task 3: 전달 불가 대기열의 후속 조정

**Files:** `server/task-continuation.ts`, `tests/task-continuation.test.ts`.
**Interfaces:** 기존 `taskSequenceBlocker`와 원래 입력의 안전한 미전송 여부를 사용한다.

- [ ] 선행 업무에 막힌 미전송 지시가 총괄 조정으로 연결되는지, 재시작 중복 방지와 수신 보호를 검사한다.
- [ ] 위임 지시를 다시 만들지 않고 기존 지시·차단 업무를 설명하는 조정 요청을 생성한다.
- [ ] 후속 실행·배정 회귀 및 전체 격리 검사 결과를 기록하고 커밋한다.
