## 목적과 현재 경로

Codex의 실제 사용 가능 도구에는 Claude Read가 없다. CommandExecution의 sed/rg 출력은 실행 증거/ToolText지만 readsSource의 Read/WebFetch가 아니다. Codex McpToolCall도 server/tool 이름을 가진 ToolText이며 임의 MCP를 Read로 추측하지 않는다. 현재 IAMCEO file은 자기 자료를 만들 뿐 원 코드 열람 근거로 쓰지 않는다.

## Approaches / 작성자가 선택한 최소 경로

1. 셸 명령/출력을 읽기로 해석: printf 위조와 셸 문법·이벤트 의존성이 커 배제한다.
2. 새 서버 열람의 결과를 제공자 MCP 기록에서만 판독: 실제 제공자 기록 형식·부분 결과·중첩 도구 이름 의존성이 남아 배제한다.
3. 서버가 제한된 코드 조각을 읽고 서버 소유 receipt와 대조: 선택한다. 기존 Store agent_operation_receipts의 서버 전용 namespace를 이용해 DBv32를 유지한다. 공통 요청 보관 정책은 바꾸지 않는다.

## 입력·권한·관찰

code_read({task_id, contract_rev, source, start_line, end_line}). source는 server/orchestrator.ts 또는 server/harness-evidence.ts 두 상대 이름만 허용한다. 절대 경로/URL/다른 파일/자유 세션/직원/본문/receipt ID 입력은 없다. 줄은1부터, 요청80줄·응답16KiB·파일2MiB 이하다. 잘림/미완료를 통과시키지 않고 거절한다.

같은 프로젝트의 확정된 현재 조사 계약(kind=research 또는 source 필수)만 받는다. 직원은 자신의 읽기 관찰을 생성하며 다른 직원의 관찰을 승계하지 않는다. 프로젝트 root에서만 파일을 정하고 현재 보호된 파일 roots·비밀 경계를 유지한다. 심볼릭 링크·하드 링크·디렉터리/FIFO·경로 탈출·보호된 root·비UTF8/NUL을 거절한다. 경로/descriptor 정체성과 읽기 전후 stat을 대조한다. 동시 변경/불완전 읽기는 거절하며 모든 ABA 경쟁을 증명했다고 하지 않는다.

응답은 원 출처 절대 식별, 읽힌 줄과 텍스트, 읽은 시각, 전체 파일/조각 SHA256, 완결 상태, 불투명 receipt 참조다. 실제 보인 조각 밖은 인용 근거로 받지 않는다. 알려진 민감 표기가 가림 함수에 걸리면 조각 전체를 거절하며 원문을 응답/receipt/오류에 내보내지 않는다. 임의 모든 비밀 문자열 탐지를 보장하지 않는다. 코드 실행·네트워크·자격값 획득은 없다.

성공 관찰은 code-read:<server UUID> namespace와 server_code_read_v1 종류로 보관한다. 외부 operation ID는 ':'를 받지 않아 이 namespace를 만들 수 없다. 동일 프로젝트/직원/요청 업무/실제 계약 업무/판/계약 시각/프로젝트 root에 묶는다. 실패·부분·잘림·이전 판·계약 전·다른 직원/업무는 채택하지 않는다. 같은 업무/직원/계약 판/root 범위에서 최대128 성공 관찰로 제한한다.

공통 agent_operation_receipts.request_json은 스키마 검사 전의 임의 요청도 원문 보관한다. 이 기존 한계를 유지·검증하고 '요청 미보관'이라고 쓰지 않는다. 새 관찰/성공 응답에는 읽기 검사를 통과한 안전 조각만 남긴다. 새 도구의 검증/읽기 오류는 입력·파일 내용이 없는 고정 문구다.

## 완료 대조·의미와 적용

completion gate가 현재 범위의 서버 관찰만 verifyClaims에 공급한다. 출처 절대 문자열은 원 주장 그대로 유지한다. 사실 인용은 읽힌 실제 조각에 정확한 문자열로 있어야 하며, 해석도 해당 출처의 열람이 있어야 한다. verified=false/semanticReview=required를 유지한다. via에는 읽은 시점·줄·snapshot/receipt를 남긴다. 이후 파일 변경을 현재 내용의 보증으로 바꾸지 않는다.

새 code_read는 기존 실행 검사·계약·일반 Read/WebFetch 기준을 바꾸지 않는다. 연구 원 주장3은 다른 직원 자료의 기존 대조를 유지한다. 정상 완료는 모든 실행 검사를 갖춘 상태에서 검사/주장 저장값을 확인한다. 출처만 미열람인 단독 반례는 다른 실패가 없음을 먼저 입증한다.

DB 구조 변경은 없지만 새 관찰 receipt는 정상 보관된다. 기존 세션은 서버 코드/도구 목록 갱신 후 새 도구가 보여야 사용할 수 있다. 과거 sed/rg를 소급 승격하지 않는다. 실제 적용/비서 재검증·도구 목록 갱신은 이번 범위 밖이며 독립 w4 재검토 뒤다. 되돌리기는 추가 코드를 빼고 기존 receipt를 보존한다. 공통 하네스7항목 전체·주장 의미 검토·환경 정책은 여전히 부분/별도다.


서버가 실제 읽기를 마친 관찰이며 클라이언트의 주의·수신 ACK를 별도 증명하지 않는다. 동일 직원/업무/판/root의 관찰은 재개 뒤에도 보존되며 세션 교체를 소급 열람으로 쓰지는 않는다. 새 세션·재개·실행 중 세션은 서버 갱신 뒤 tools/list에서 code_read 존재를 확인해야 한다. 실제 클라이언트의 목록 갱신·재연결 절차는 미검증이다. 기존 테이블 조회 비용·보관량·모든 동시 파일 ABA 경쟁과 임의 비밀 문자열 탐지는 보장 범위 밖이다.
