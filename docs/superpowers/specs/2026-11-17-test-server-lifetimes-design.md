# 검증용 서버의 실행 수명 관리

사용자가 2026-11-17 서버 운영 개선을 하나씩 실행하도록 승인했다. 첫 작업은 검증용 서버가 실패·시간 초과·실행기 종료 뒤 남지 않도록 하는 것이다. Docker 구성과 운영 서버의 상시 실행, 실제 직원·대화·승인·core 세션은 유지한다.

남은 IAMCEO 소스 서버들은 `iamceo-hup-*`, `iamceo-orphan-*` 임시 DB를 연다. `screens-regress.browser.ts`의 두 강제 종료 검사는 서버를 실행한 뒤 가짜 실행 로그를 기다리는 단계가 실패하면 종료 경로를 건너뛴다. 공통 서버와 재시작 뒤 서버만 정리되는 구조가 누적을 허용한다.

검증 서버를 실행 즉시 등록하는 테스트 전용 scope를 추가한다. scope는 임시 IAMCEO_HOME과 IAMCEO_TEST=1을 요구하고, 종료 요청 뒤 실제 종료를 기다린다. 2초의 정리 예산을 넘는 경우 이 scope가 직접 만든 검증 프로세스만 강제 종료한다. Bun의 `--no-orphans`로 실행기 강제 종료를 감시한다. 테스트 전용 preload는 네이티브 감시가 시작된 뒤 Bun이 내보낸 환경변수를 지워, 독립 core 제공자에 수명 정책이 전달되지 않도록 한다. Bun 1.3.14와 1.4.4에서 부모 종료와 환경 격리를 함께 검증한다.

운영 서버의 부모 종료 정책이나 core 소유 실행의 정책은 바꾸지 않는다. 이번 범위는 `screens-regress.browser.ts`의 소스 서버 실행 전체와 `cli.test.ts`의 공통 소스 서버 helper다. 다른 browser suite와 컴파일된 CLI 감독 프로세스 검사는 기존 정리 경로를 유지하며 이번 보장 범위에 포함하지 않는다.

완료 조건은 실제 subprocess를 쓰는 실패 정리·정리 시간 제한·부모 강제 종료·격리 경계·환경 전파 방지 검사 통과, 기존 실패 시에도 잔여 서버 0개 확인, 타입 검사·빌드 확인, 소유권을 증명한 기존 검증 서버 정리와 운영 서버 보존 확인이다. 기존 강제 종료 검사 2개는 이번 변경 전부터 가짜 제공자 시작을 기다리다 실패한다. 이를 통과시키기 위해 격리 fixture의 경로·환경·네트워크 제한을 완화하지 않는다. 전체 검사의 기존 실패는 별도로 보고한다. 비밀 값과 실행 데이터는 Git 밖에 보존한다.
