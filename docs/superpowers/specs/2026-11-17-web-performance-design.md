# Web performance improvements

The user approved the selective optimization order from `docs/research/2026-11-17-upstream-native-performance.md`: reduce repeated delivery/status reads, reuse identical compact sync responses, and retain unchanged web state references. Scope is the current web and its server read paths. Native clients, worker execution/recovery policy, storage encoding, approval rules and database schema are unchanged.

- R1. Delivery notice reads must stop scanning unrelated message history and repeating per-delivery recovery reads. A1: a controlled SQLite fixture grows from 40 to 240 queued deliveries without proportional SQL statement growth; notice values, previews, failed-message handling and cursors remain equal to the uncached calculation. Read scope ends synchronously and retains no data across requests.
- R2. Concurrent compact sync readers may reuse completed JSON bytes. A2: repeated concurrent requests reuse project-state construction; database writes, cursor changes, incoming Host, managed SSH settings, project and projection changes invalidate or partition results. Cache only successful compact syncs; 250ms TTL, at most 32 entries and 8MiB UTF-8 total. Invalid/authentication/write requests remain outside the cache. Expired lease/time-dependent reads are never retained beyond the TTL.
- R3. Equal web domain payloads retain stable object/array references and unchanged rows across updates. A3: equal snapshots retain their references; changing member status while configuration revision is unchanged still updates that member and preserves unrelated collections. Order, additions/removals, project switches, message overlays, logout and stale-generation protection remain correct.
- R4. Verify gains and preserve existing service state. A4: measure SQL statement counts and snapshot construction counts on identical isolated fixtures; verify a real browser renders current changes while unchanged rows retain identity. Before deployment compare the latest active release, preserve terminal PID/session/approval identities, and verify the immutable release over Tailscale.

Use the upstream implementations as references; do not merge their full commits or remove the web client. A short compact-response cache complements paging/gzip and reduces concurrent duplicate work, rather than suppressing legitimate updates. Resolve current connection settings before cache lookup so address changes remain immediate.

The web reconciliation helper operates on JSON domain values without mutating either input. Runtime fields are compared as data, not inferred from CAS revisions. No UI labels or explanatory screens are added.

Read completion is tracked independently from shared domain identity. Conflict forms can accept a fresh but equal snapshot for re-review; an older write response cannot claim ownership merely because its optimistic value stayed equal. A buffered local event still triggers the coordinator’s authoritative follow-up read. Regression coverage includes that ordering as well as equal confirmed values.
