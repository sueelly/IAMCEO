# 실행 복구와 대기 원인 표시

사용자는 반복 종료의 원인 해결, 사용량 한도 오류의 별도 표시, 보고 길이 제한의 권고 전환, 대기 이유의 세분화를 실행하도록 요청했다. 기존 전역 동시 실행 한도 20은 유지한다.

확인된 원인: 보존된 Codex 화면은 `No saved session found with ID`를 남겼다. 저장 대화가 없는 상태에서 재개를 실행한 뒤 즉시 종료하고, offline 직원의 대기 입력이 같은 재개를 다시 호출했다. 조회 실패·대화 부재·입력 처리 불확실성을 구분해야 한다.

- R1. 서버는 확인된 대화 부재를 실행 전에 식별하고 기존 인계 경로로 복구한다. 확정되지 않은 부재는 새 대화로 바꾸지 않는다. 비정상 종료 뒤에는 원인 확인 없이 같은 프로그램을 계속 열지 않는다.
- A1 → R1. 없는 Codex 대화는 terminal.run 전에 식별된다. 기존·보관된 대화와 살아 있는 소유 터미널은 유지된다. 파일 접근 오류와 불확실한 생성·전달은 새 실행으로 바뀌지 않는다. 비정상 종료 뒤 반복 tick·서버 재구성에서 실행 수가 증가하지 않고 명시적 재개에서만 재시도한다.
- R2. 서버와 웹은 제공자 사용량 한도·인증·시작 실패를 구분한다.
- A2 → R2. weekly limit, usage/rate limit 오류가 ‘사용량 한도’로 표시되고 일반 연결 오류와 구분된다. 한도 상태에서 자동 입력을 반복하지 않고 명시적 재개 또는 실제 정상 실행 관측으로 해제한다.
- R3. 보고의 텍스트 길이 기준은 권고로 취급하며 긴 원문을 손실 없이 저장한다.
- A3 → R3. 500자를 넘는 명령과 1,000자를 넘는 근거·기타 보고 설명을 접수하고 권고를 반환한다. 동일 실행 증거와 출처 검증은 통과해야 하며 길이를 이유로 완료 결과를 잘라 저장하거나 검증을 우회하지 않는다.
- R4. 웹은 전달을 실제로 가로막는 이유를 해당 직원·업무에 표시한다.
- A4 → R4. 동시 실행 자리, 현재 실행, 선행 업무, 수동 터미널 조작, 승인·선택, 압축, 재시도 시각, 실행기·세션 문제, 프로젝트 실행 중지와 보호 입력을 구분한다. 해제된 이유는 지워지고 실행 중인 업무에 과거 대기 이유가 남지 않는다.

구현 선택: 기존 복구·큐 경계에 실패 상태와 대기 관측을 추가한다. 한도를 더 늘리거나 수신 불명 입력을 강제 재전송하는 방법은 원인을 해결하지 못하므로 사용하지 않는다. 오류는 지속 기록하고 대기 관측은 실행기에 맞춰 갱신한다. 화면에는 판단에 필요한 실제 사유만 표시한다.

운영 데이터·비밀은 Git 밖에 둔다. 다른 실행·승인·대화는 보존한다. 작업 브랜치 커밋·일반 푸시와 원격 SHA 확인까지 수행한다. main 통합은 이 저장소에서 별도 지속 승인된 권한이 아니다. 운영 반영은 진행 CLI를 보존하는 기존 릴리스 절차를 확인한 뒤 수행 가능 범위를 구분한다.
