# 며칠 뒤에도 이해할 수 있는 IAMCEO 출력

IAMCEO의 대화·자료·팀 상태·업무 보고·결재 요청에서 대상과 맥락이 사라지지 않도록 한다. 사용자는 2026-11-18에 목적에 맞는 구성, 핵심 우선, 정보의 관계, 분명한 문장, 알맞은 표현 방식, 선택적 강조, 확정 상태 보존, 가까운 근거, 필요한 시각화, 완성된 결과물 제공의 10가지 원칙을 적용하라고 요청했다.

## 확정 요구와 완료 조건

- R1. 모든 직원 종류와 지원 CLI의 공통 작성 프롬프트에 10가지 원칙을 적용한다. 사용자 정의 역할도 공통 지침을 받는다. A1: 기본·사용자 정의·내보낸 역할과 CLI에 전달되는 프롬프트를 확인한다.
- R2. 독자가 앞선 대화를 다시 찾지 않아도 업무명, 요청한 결과, 현재 결과, 남은 확인 대상과 다음 행동을 파악할 수 있게 한다. 정보가 없으면 누락된 대상을 구체적으로 밝히며 추측하지 않는다. A2: 팀 상태·보고·결재·자료의 도구 설명을 대조하고 설명 없는 ‘원ID’·‘원 지시’의 검사 경고를 확인한다.
- R3. 글자·줄 수와 강조 개수에 맞추려고 목적어·조건·근거를 빼게 하는 지침과 경고를 없앤다. 배포·재시작·검증처럼 다른 행위를 한 용어로 치환하지 않는다. A3: 긴 문장, 여러 판단 지점의 강조, 근거 식별자를 포함한 구체적 보고에 축약 요구가 발생하지 않는다. 도구의 구조·권한·전송 제한은 보존한다.
- R4. 진척 없는 자동 후속 요청이 결재로 전환될 때 프로젝트·업무·요청 내용·최근 보고·남은 검사·확인한 범위를 본문에 넣는다. 후속 조정 횟수를 구현이나 검사 횟수로 표현하지 않는다. A4: 실제 coordinator를 메모리 DB에서 실행해 생성된 결재와 전달문을 검사한다. 자료가 없거나 다른 업무의 기록이면 확인할 수 없다고 쓴다.
- R5. 원문·시각·수치·실제 확인 상태를 보존한다. 과거 운영 보고와 결재를 다시 쓰거나 답변하지 않는다. A5: 기존 실행·대기·승인·완료 판정 회귀가 통과하고 원본 보고가 바뀌지 않는다.

## 구현 범위

공통 작성 지침, 역할 조립, 작성 도구 설명·비차단 경고, 자동 후속 조정의 결재/직원 입력을 수정한다. 화면마다 안내문을 추가하지 않는다. 공통 프롬프트 적용은 모델이 앞으로 작성할 출력의 지침이며 모든 자연어 결과의 품질을 보증하는 의미 검증기는 아니다. 과거 자료의 일괄 수정이나 직원 실행 재개는 이 작업에 포함하지 않는다.

개발·검증·커밋·작업 브랜치 푸시를 수행한다. 운영 서비스의 main 통합·재시작은 작업 브랜치 푸시와 구분한다.
