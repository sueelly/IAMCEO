# 긴 팀 화면을 직원별 요약과 상세로 나누는 설계

상태: 검토용 제안. 사용자가 요청한 범위는 설계와 예시 화면이다. 운영 화면 구현·반영은 이 산출물에 포함하지 않는다.

## 목적과 현재 근거

God of the world의 여러 직원이 무엇을 하는지 비교할 때 한 직원의 과거 업무를 끝까지 스크롤하지 않아도 되게 한다. 기존 Glass 색상·서체·버튼·내비게이션과 업무 상태의 의미를 유지한다.

2026-11-18 03:01 KST 운영 조회에서 직원 11명, 흐름에 표시되는 고유 업무 170개, 담당별 표시 252개를 확인했다. 총괄의 담당별 표시는 67개다. 완료 카드를 일부 접은 실제 화면에는 카드 243개가 렌더링됐다. 1440×1000 Chromium에서 업무 흐름 높이는 약 22,972px, 전체 팀 스크롤 높이는 약 33,047px였다. 실행 중 표시 13개는 업무별 표시 수이며 동시 직원 세션 수를 뜻하지 않는다.

근거 원본·실제 제목을 포함한 예시와 화면은 Git 밖 private/god-team-density-20261118에 보관한다. 위 수치는 관측 당시 값이며 현재 실시간 수치가 아니다.

## 비교한 구조

| 방식 | 장점 | 한계 |
| --- | --- | --- |
| 직원별 전체 카드 접기 | 변경이 작고 기존 화면을 유지한다. | 접힌 직원의 지금·다음 업무를 비교하려면 계속 열어야 한다. |
| 열마다 높이를 제한하고 내부 스크롤하기 | 카드 표현을 그대로 쓴다. | 직원 수만큼 스크롤 영역이 생기며 남은 업무를 놓치기 쉽다. |
| 직원별 요약 행과 하나의 상세 패널 | 직원 전체를 같은 열에서 비교하고 선택한 범위만 자세히 본다. | 요약으로 뽑은 업무 외에 몇 개가 더 있는지 정확히 표시해야 한다. |

세 번째를 에이전트의 추천으로 제안한다. 사용자가 아직 최종 선택한 것은 아니다. 요청한 예시에서 실제 구성으로 살펴볼 수 있게 한다.

## 화면과 상호작용

기본 화면은 직원별로 직원 이름, 지금, 다음·대기, 확인 필요, 최근 완료를 한 행에 보여준다. 데스크톱 행은 약 60px이며 제목은 두 줄까지 표시한다. 한 셀에 나머지 카드를 쌓거나 별도 스크롤을 만들지 않는다. 직원 이름을 누르면 담당한 모든 업무를 볼 수 있다. 기존 직원 설정·터미널·승인 조작은 직원 상세에서 계속 제공하는 것이 구현 제안이며 예시에서는 실행하지 않는다.

‘지금’은 현재 실행 근거가 있는 업무를 우선하고, 없으면 막힌 업무·검토할 업무를 표시한다. 같은 실행 상태의 업무가 더 있으면 ‘외 N’으로 그 상태의 남은 수를 표시한다. 실행 중 옆에 검토·막힘까지 합한 수를 붙이지 않는다. 다른 확인 업무의 수는 확인 필요 열에 표시한다. 대표 업무를 뽑는 규칙은 화면 표시만 바꾸며 실행 대기열을 재정렬하지 않는다. 대표가 중단했거나 승인·입력 확인이 필요한 업무는 확인 필요 열의 수에 반드시 포함한다.

‘다음·대기’는 기존 서버의 순서와 라벨을 보존한다. 실행 지시를 받았다는 근거가 없는 보고·진행판 기록을 새 실행 약속으로 바꾸지 않는다. 완료 확인 대기와 다음 실행 예정은 원래 상태 라벨로 구분한다. 최근 완료는 완료 근거가 있는 업무 중 가장 최근 하나와 남은 완료 수를 보여준다. 턴이 끝났거나 보고 제목에 완료라고 쓰였다는 이유로 완료로 바꾸지 않는다.

기존 workflowBucket과 workflowCategory를 요약과 상세에 함께 사용한다. unknown은 지금 및 확인 필요에 포함하고 실제 실행 중으로 표시하지 않는다. current가 true인 waiting도 지금 및 확인 필요에 남긴다. historical인 미완료 기록도 확인 필요에서 제외하지 않는다. 이 규칙은 담당 직원이 있는 노드에 적용하며 미배정·완료 우선 분류는 기존 규칙을 유지한다.

확인 필요 열은 막힘과 검토·기타 확인 수를 구분한다. 수를 누르면 해당 직원과 상태가 선택된 상세 패널을 연다. 같은 업무를 여러 직원이 맡으면 각 직원의 담당 건수에는 들어가지만 상단 전체·상태 필터 수는 기존 고유 업무 집계 규칙을 따른다.

상세 패널은 데스크톱 오른쪽에서 열리고 내부에서만 스크롤한다. 전체·지금·다음·확인 필요·완료 탭으로 범위를 바꾼다. 특정 제목을 눌러 열면 해당 항목을 펼치고 패널 안에서 보이는 위치로 이동한다. 목록과 상세에서 전체 제목, 원래 상태, 이유, 마지막 보고, 부모·파생 연결을 볼 수 있다. 열었다 닫아도 뒤의 필터·검색·스크롤·키보드 초점이 유지된다. 열린 목록에 변화가 오면 선택 업무를 유지하고 숫자만 갱신하며 다른 직원을 자동 선택하지 않는다.

우클릭과 접근 가능한 ‘연결만 보기’ 동작은 기존 직접 연결 범위를 유지한다. 집중 보기에서만 관련 업무를 펼쳐 보여주고 전체 보기로 복귀하면 원래 필터와 스크롤로 돌아온다. 미배정은 상단 숫자 버튼으로 열어 전체 목록을 탐색한다. 운영 구현에서 기존 드래그→인계 검토→확정 경로를 유지하며 실제 배정·승인·중단·계약 검사를 우회하지 않는다. 이 예시는 배정을 보내지 않는다.

휴대폰에서는 직원당 현재 업무 한 개와 다음·대기/확인 필요/완료 숫자를 담은 짧은 행으로 재배치한다. 상세는 아래에서 올라오는 패널로 연다. 가로 스크롤을 만들지 않고 나머지 업무는 동일한 상세에서 확인한다.

‘전체 카드’는 기존 구조와 비교할 수 있도록 예시에 제공한다. 실제 구현에서는 기본 요약 화면 아래에 같은 직원 카드와 업무 목록을 다시 쌓지 않는다. 직원 조작은 직원 상세, 전체 업무 탐색은 필터와 상세로 연결한다. 목록의 모든 내용을 숨겨 길이만 줄이는 방식은 채택하지 않는다.
