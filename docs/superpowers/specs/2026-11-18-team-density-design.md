## 화면과 상호작용

기본 화면은 직원별로 직원 이름, 지금, 다음·대기, 확인 필요, 최근 완료를 한 행에 보여준다. 데스크톱 행은 약 60px이며 제목은 두 줄까지 표시한다. 한 셀에 나머지 카드를 쌓거나 별도 스크롤을 만들지 않는다. 직원 이름을 누르면 담당한 모든 업무를 볼 수 있다. 기존 직원 설정·터미널·승인 조작은 직원 상세에서 계속 제공하는 것이 구현 제안이며 예시에서는 실행하지 않는다.

‘지금’은 현재 실행 근거가 있는 업무를 우선하고, 없으면 막힌 업무·검토할 업무를 표시한다. 같은 실행 상태의 업무가 더 있으면 ‘외 N’으로 그 상태의 남은 수를 표시한다. 실행 중 옆에 검토·막힘까지 합한 수를 붙이지 않는다. 다른 확인 업무의 수는 확인 필요 열에 표시한다. 대표 업무를 뽑는 규칙은 화면 표시만 바꾸며 실행 대기열을 재정렬하지 않는다. 대표가 중단했거나 승인·입력 확인이 필요한 업무는 확인 필요 열의 수에 반드시 포함한다.

‘다음·대기’는 기존 서버의 순서와 라벨을 보존한다. 실행 지시를 받았다는 근거가 없는 보고·진행판 기록을 새 실행 약속으로 바꾸지 않는다. 완료 확인 대기와 다음 실행 예정은 원래 상태 라벨로 구분한다. 최근 완료는 완료 근거가 있는 업무 중 가장 최근 하나와 남은 완료 수를 보여준다. 턴이 끝났거나 보고 제목에 완료라고 쓰였다는 이유로 완료로 바꾸지 않는다.

기존 workflowBucket과 workflowCategory를 요약과 상세에 함께 사용한다. unknown은 지금 및 확인 필요에 포함하고 실제 실행 중으로 표시하지 않는다. current가 true인 waiting도 지금 및 확인 필요에 남긴다. historical인 미완료 기록도 확인 필요에서 제외하지 않는다. 이 규칙은 담당 직원이 있는 노드에 적용하며 미배정·완료 우선 분류는 기존 규칙을 유지한다.

확인 필요 열은 막힘과 검토·기타 확인 수를 구분한다. 수를 누르면 해당 직원과 상태가 선택된 상세 패널을 연다. 같은 업무를 여러 직원이 맡으면 각 직원의 담당 건수에는 들어가지만 상단 전체·상태 필터 수는 기존 고유 업무 집계 규칙을 따른다.

상세 패널은 데스크톱 오른쪽에서 열리고 내부에서만 스크롤한다. 전체·지금·다음·확인 필요·완료 탭으로 범위를 바꾼다. 특정 제목을 눌러 열면 해당 항목을 펼치고 패널 안에서 보이는 위치로 이동한다. 목록과 상세에서 전체 제목, 원래 상태, 이유, 마지막 보고, 부모·파생 연결을 볼 수 있다. 열었다 닫아도 뒤의 필터·검색·스크롤·키보드 초점이 유지된다. 열린 목록에 변화가 오면 선택 업무를 유지하고 숫자만 갱신하며 다른 직원을 자동 선택하지 않는다.

우클릭과 접근 가능한 ‘연결만 보기’ 동작은 기존 직접 연결 범위를 유지한다. 집중 보기에서만 관련 업무를 펼쳐 보여주고 전체 보기로 복귀하면 원래 필터와 스크롤로 돌아온다. 미배정은 상단 숫자 버튼으로 열어 전체 목록을 탐색한다. 운영 구현에서 기존 드래그→인계 검토→확정 경로를 유지하며 실제 배정·승인·중단·계약 검사를 우회하지 않는다. 이 예시는 배정을 보내지 않는다.

휴대폰에서는 직원당 현재 업무 한 개와 다음·대기/확인 필요/완료 숫자를 담은 짧은 행으로 재배치한다. 상세는 아래에서 올라오는 패널로 연다. 가로 스크롤을 만들지 않고 나머지 업무는 동일한 상세에서 확인한다.

‘전체 카드’는 기존 구조와 비교할 수 있도록 예시에 제공한다. 실제 구현에서는 기본 요약 화면 아래에 같은 직원 카드와 업무 목록을 다시 쌓지 않는다. 직원 조작은 직원 상세, 전체 업무 탐색은 필터와 상세로 연결한다. 목록의 모든 내용을 숨겨 길이만 줄이는 방식은 채택하지 않는다.

## 2차 설계: 직원 상세 연결과 전체 지도

사용자는 요약판을 기존 직원 상세 팝업과 연결하고 아래에 반복되는 영역을 정리하는 방향을 요청했다. 전체 지도에서는 큰 업무별 진행·막힘, 직원 사이 연결, 업무 선후관계가 모두 중요하며 이 순서로 강조하도록 확정했다. 이번 단계도 설계와 예시이며 운영 구현 착수로 확대하지 않는다.

### 직원 상세를 하나의 진입점으로 통합한다

직원 이름은 기존 MemberDetail 주소와 직원 ID를 사용한다. 별도의 직원 상세를 중복 생성하지 않고 같은 팝업에 요약·업무·활동·실행/설정을 나눈다. 업무 제목과 막힘 숫자를 누르면 같은 팝업의 업무 탭에서 해당 범위를 연다. 팝업 안의 업무를 선택해 지도에 집중했다가 돌아와도 직원·탭·선택 업무와 뒤의 필터·스크롤을 유지한다.

현재·다음·문맥, 결재 대기, 직접 지시, 승인 패널, 전달 보류와 재확인, 활동, 터미널, 중단·재우기·깨우기, 새 세션, CLI·모델·effort를 보존한다. 최근 main에 추가된 실행 오류와 대기 이유도 생략하지 않는다. 승인과 실제 쓰기는 기존 버전·소유권·연결 검사와 API 경로를 그대로 사용한다. 승인 대기는 다른 탭을 보고 있어도 상세 머리말의 상황 알림에서 접근할 수 있게 한다. 예시에서는 쓰기·터미널 입력·승인 응답을 실행하지 않는다.

| 기존 하단 영역 | 새 진입점 |
| --- | --- |
| 총괄·직원 카드와 잠든 직원 | 요약판의 모든 직원 행 → 동일한 직원 상세. 잠든 직원도 목록과 검색에 남는다. |
| 전체 업무 목록 | 상단 상태 필터·검색·업무 상세·전체 지도. 담당 기록이 없는 업무도 미배정에서 찾는다. |
| 프로젝트의 지금 상황 | 상단 팀 메뉴의 팀 상황 및 총괄 상세 요약. 직원의 검증된 실행 상태로 혼동하지 않는다. |
| 개발 기억 | 상단 팀 메뉴. 프로젝트 설정을 직원 개인 설정으로 바꾸지 않는다. |
| 직원 추가·총괄 시작 | 상단 팀 메뉴 및 직원이 없는 첫 화면. 실행이 꺼진 경우 필요한 시작 경로를 유지한다. |
| 기존 작업판의 독립 기록 | 업무로 연결된 기록은 업무 상세, 연결되지 않은 기록은 전체 업무의 진행판 기록 범위로 접근한다. 일괄 삭제하거나 완료로 바꾸지 않는다. |

### 전체 지도는 업무 ID로 합치고 단계적으로 펼친다

2026-11-18 03:26 KST 추가 조회에서 고유 업무 172개와 담당별 표시 255개를 확인했다. 실제 부모 관계가 있는 묶음 5개와 개별 업무 74개가 있다. 가장 큰 부모 묶음은 90개 업무를 포함한다. 이 원본에 기반해 6개 묶음으로 전체 범위를 제시한다. 개별 업무 묶음은 화면상의 모음이며 새 부모 업무나 의존 관계를 생성하지 않는다. 같은 업무를 여러 직원이 맡아도 지도 노드는 하나고 담당자 목록을 함께 표시한다.

기본 지도는 각 묶음의 전체 업무 수, 막힌 업무 수, 확인·실행·다음·완료 분포와 담당 직원을 보여준다. 직원 이름을 선택하면 담당 연결을 강조하거나 직원 상세를 연다. 직원 참여는 전달·보고·진행판의 기존 근거를 보존하며 작업 등록자를 새 담당자로 해석하지 않는다. 업무 관계를 직원 간 인계 완료로 바꾸어 설명하지 않는다.

묶음 사이의 선은 원본 직원별 순서 관계를 모아 보여주는 연결이다. 양방향 관계를 한 묶음 전체의 착수 조건처럼 그리지 않도록, 기본 지도에서는 화살표 없는 연결과 관계 건수를 표시한다. 선을 선택하면 직원 이름과 원래 업무 A → 업무 B를 보여준다. 방향 있는 선후관계는 이 개별 업무 수준에서 읽는다. 부모·파생 관계와 직원별 순서 관계는 종류·선 모양·범례로 구분한다.

묶음을 선택하면 전체 업무 목록을 열고, 업무를 선택하면 원래 지시·상태 근거·참여 직원과 실제 직접 연결 지도를 연다. 연결 지도에서는 선택 업무를 중심으로 선행/부모와 다음/파생을 나눈다. 여러 직원에게 동시에 발생한 상태는 하나의 완료 상태로 덮지 않고 담당별 상태를 상세에 남긴다. 직접 연결이 많으면 각 방향의 표시 수와 남은 수를 함께 보여주며 나머지 목록에 접근할 수 있게 한다. 현재 실행·막힘을 우선 노출해도 실행 순서는 변경하지 않는다.

지도는 고정 높이 안에서 확대·축소·맞춤과 이동을 제공한다. 필터·검색·선택 직원은 요약판과 공유하고, 지도에서 돌아올 때 이전 보기 위치를 복원한다. 화면에 없는 업무를 숨겼다면 필터 결과 수와 접힌 업무 수를 구분한다. 미배정·독립 업무·부모가 없는 업무·과거 담당·순환 관계는 누락하지 않고 원래 정보가 없는 부분을 임의로 채우지 않는다.

### 2차 예시 완료 조건

- 직원명은 통합 팝업의 요약을 열고, 업무명·상태 숫자는 업무 탭을 연다. 팝업의 탭·닫기·복귀를 확인한다.
- 기존 하단 영역의 각 기능이 위 표의 새 진입점에 대응한다. 예시의 쓰기 기능은 비활성이고 운영 요청이 발생하지 않는다.
- 지도 묶음의 고유 업무 합계가 172이며 255개 담당별 표시에서 참여 직원과 근거가 손실되지 않는다.
- 묶음 연결의 모든 원본 관계를 추적할 수 있고, 상세 지도에 표시한 선에는 원본 부모·파생 또는 직원별 순서 근거가 있다.
- PC·휴대폰, 오프라인 파일, 직원 선택·지도 집중·확대/축소·목록·돌아가기 동작을 확인한다. 실제 데이터와 결과물은 Git 밖에 둔다.

### 예시에서 구체화한 선택

설계 담당자는 기본 화면에 모든 원본 카드를 나열하는 방식 대신 실제 부모 관계의 묶음 지도를 선택했다. 전체 카드 방식은 현재 3만 px 이상의 화면을 다시 만들고, 직원 중심 연결만 표시하는 방식은 사용자가 가장 중요하게 둔 큰 업무의 진행·막힘을 뒤로 밀기 때문이다. 이 선택은 검토용 제안이며 사용자의 운영 적용 승인으로 기록하지 않는다.

- 묶음의 제목은 부모 업무의 직접 연결 지도를 열고, 업무 수는 전체 목록을 연다. 공통 부모가 없는 개별 업무 제목은 목록을 연다. 확인·막힘 숫자는 정확히 해당 범위만 연다.
- 지도에서 직원을 선택하면 관련 묶음과 실제 직원별 순서 선을 강조한다. 카드의 직원 칩과 `외 N`은 동일한 직원 상세 또는 참여 직원 전체 목록을 연다.
- 모바일은 전체 범위를 보는 작은 지도와 읽기 쉬운 전체 목록을 함께 제공한다. 자세한 제목을 읽으려고 계속 확대하도록 요구하지 않는다.
- 예시 활동 탭은 업무의 마지막 기록만 재현한다. 기존 활동 전체·터미널·결재·개발 기억·독립 진행판 원문은 수집하지 않았으며 실제 구현에서 원래 구성요소와 상태를 보존해야 한다.
- 추론 수준은 이번 스냅샷에서 별도 설정값을 수집하지 못했다. 예시에는 미수집으로 표시하며 실제 계정 설정을 추정하지 않는다. 운영 구현은 기존 MemberConfig의 실제 값을 사용한다.

별도 설계 검토 결과, 구현 계획 전에 사용자가 추가로 결정해야 할 중요한 질문은 없었다. 실제 구현은 이 설계 예시와 운영 데이터의 차이를 유지하며 별도 단계에서 진행한다.

마지막 범위 대조에서 업무 메타데이터 200개 중 흐름 밖 기록 28개도 확인했다. 서버는 합쳐진 업무·실행되지 않은 서버 기록·기존 진행판 처리 기록 등을 흐름에서 제외할 수 있다. 스냅샷에 개별 제외 이유는 없으므로 이를 완료나 미배정으로 추정하지 않는다. 지도 아래 ‘흐름 밖 기록 28’과 팀 메뉴의 진행판 기록에서 원래 제목·부모·시각을 확인하고, 텍스트에도 28개를 별도로 남긴다. 운영 구현에서는 기존 진행판의 원문과 판정을 함께 연결한다.
